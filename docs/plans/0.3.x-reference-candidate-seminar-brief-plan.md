# SeminarArc 0.3.x Reference Candidate + Seminar Brief Plan

Status: READINESS_PASS
Access date for external sources: 2026-08-31

## Goal

Turn selected local seminar evidence into transparent, reviewable reference candidates and an app-owned editable Seminar Brief.

`0.3.x` is the first SeminarArc stage that may contact external metadata services. It must remain opt-in, seminar-scoped, provider-independent, and review-first.

## User Value

- Recover paper titles, DOI, authors, venues, methods, datasets, and related-work clues from selected slide OCR or user input.
- Let the user confirm or reject candidates with visible evidence, not hidden ranking.
- Produce an editable Seminar Brief that links confirmed references, key slides, questions, and follow-up actions into one exportable document.

## Provider Choice

First version recommendation:

- Primary: Crossref REST API.
- Secondary: OpenAlex Works API for fallback and cross-confirmation.
- Targeted fallback: DataCite REST API when DOI/resource clues indicate dataset, software or non-Crossref DOI.
- Deferred: Semantic Scholar Academic Graph API until commercial/license and attribution decisions are explicitly approved.

Rationale:

- Crossref gives the cleanest DOI-first path and directly supports “I have metadata, what is the DOI?” use cases.
- OpenAlex is broader and CC0, but the current credit/budget model makes it better as a fallback/cross-check than as the only provider for every noisy OCR query.
- DataCite is valuable for datasets/software, but should not replace Crossref/OpenAlex for ordinary papers.
- Semantic Scholar has useful graph metadata, but its license is not frictionless for an app that may later monetize.

## Evidence Extraction

Allowed evidence inputs:

- User-selected OCR text from a single photo or selected lines.
- OCR from `KEY_SLIDE` or `REFERENCE` tagged photos, only when the user selects them.
- Seminar metadata: title, speaker, affiliation, scheduled year, abstract text selected by the user.
- User-entered DOI, title, author, venue or year clue.
- User-selected question/note text.

Disallowed default inputs:

- Entire seminar OCR corpus.
- Raw photos, recordings, clips, abstract PDFs or ZIP/Markdown archive.
- Full timeline or all notes by default.

### DOI Extraction

Use deterministic extraction before fuzzy search:

- Regex: case-insensitive `\b10\.\d{4,9}/[-._;()/:A-Z0-9]+\b`.
- Normalize `doi:`, `DOI`, `https://doi.org/`, `http://dx.doi.org/`, surrounding brackets and trailing punctuation.
- Lowercase DOI, preserve slash suffix, URL-encode for request path/query.
- OCR repair candidates before lookup: `l`/`I`/`1`, `O`/`0`, en dash/em dash to hyphen, spaces around slash, broken line wrap.
- Exact DOI lookup overrides fuzzy ranking; if provider DOI disagrees after normalization, keep both as separate pending candidates.

### Bibliographic Clues

First version uses deterministic heuristics only:

- Title-like lines: 5-24 tokens, not mostly uppercase section headers, not ending with citation punctuation, high alphabetic ratio, near `References`/`Related Work`/title slide context.
- Author-like lines: comma/and-separated names, initials, repeated capitalization, ORCID/ROR not required.
- Year: four-digit year 1900-current year+1; prefer years near title/author lines or citation patterns.
- Venue: lines after journal/conference markers or common abbreviations; user confirmation required.
- Method/dataset clue: store as evidence tags, not direct metadata fields unless provider returns a match.

Manual user confirmation is required before issuing title/author/year search when OCR quality is low or multiple title-like lines conflict.

## Candidate Ranking And Dedup

Scores are deterministic match scores, not probabilities. UI must display bands and reasons, not fake precision.

### Dedup

1. Normalize DOI and merge candidates with the same DOI.
2. If DOI is absent, merge by normalized title plus publication year plus first-author family-name overlap.
3. Preserve all provider provenance in `providerEvidenceJson`.
4. Prefer confirmed DOI/title/author data over provider-specific display variants, but never overwrite user edits silently.

### Score Components

Maximum score: 100.

- DOI exact normalized match: 100 and `HIGH_CONFIDENCE`, unless provider metadata contradicts selected title/author severely.
- Title similarity: up to 35 using normalized token similarity plus ordered significant-token overlap.
- Author overlap: up to 20, based on family-name overlap and first-author match.
- Year proximity: up to 10; exact year 10, +/-1 year 6, otherwise 0.
- Venue/source match: up to 10.
- Provider cross-confirmation: up to 10 when Crossref/OpenAlex/DataCite agree on DOI or normalized title/year.
- Evidence quality: up to 10 from OCR confidence, user-edited OCR, `REFERENCE` tag, and manual clue source.
- Query type bonus: DOI +15 cap handled by override; exact title/manual clue +5; noisy OCR search +0.

Bands:

- `HIGH_CONFIDENCE`: exact DOI or score >= 75 with title plus author/year agreement.
- `POSSIBLE_MATCH`: score 50-74.
- `NEEDS_REVIEW`: score 30-49 or any contradictory key field.
- Below 30: hidden by default behind “show low confidence” and never auto-confirmed.

Tie handling:

- Confirmed exact DOI wins.
- Then higher title+author combined score.
- Then provider cross-confirmation count.
- Then more complete metadata.
- Remaining ties sort alphabetically by title for stability.

## Network / Privacy / Cache Contract

- Lookup is opt-in and seminar-scoped.
- Before network request, show query preview and provider list.
- Default outbound payload is minimal: DOI or selected bibliographic clue only.
- Never send photos, recordings, clips, abstract PDFs, full OCR corpus, full timeline or exported archives.
- Use `User-Agent` with app identity and contact route for Crossref/OpenAlex polite behavior; do not embed paid API secrets.
- Store provider metadata as app-owned cache tied to seminar/candidate. Suggested TTL: no automatic refresh for confirmed candidates; pending/rejected cache can be refreshed manually after 30 days.
- Delete seminar deletes evidence, lookup attempts, candidates, brief and provider payload cache.
- 429: honor `Retry-After` where present, exponential backoff otherwise, and keep local Reconstruction usable.
- Timeout: 10s connect, 20s read for first version; show partial provider results if one provider succeeds.
- Offline: no request; show cached candidates and allow evidence editing.
- Logs must not include raw OCR query text, DOI beyond normalized safe display, provider API keys or full payload.

## UX Flow

```text
Research Reconstruction
  -> select evidence
  -> Find references
  -> Query preview
  -> Lookup
  -> Candidate Review
  -> Confirm / Reject
  -> Seminar Brief
  -> Markdown/ZIP export
```

Candidate UI:

- List rows show title, first authors, year, venue, DOI, provider badges, confidence band and 1-3 match reasons.
- Detail view shows side-by-side selected evidence and provider metadata.
- Duplicate DOI rows merge and show provider provenance.
- Low confidence candidates stay collapsed behind “Needs review”.
- Confirm/reject is reversible.

Brief UI:

- One seminar-scoped editor.
- Pre-populate only safe local hints: seminar title/speaker/date, confirmed references, key slides and selected questions/notes.
- All prose fields are user-edited text; no AI generated copy in `0.3.x`.
- Existing Markdown/ZIP export gains optional Brief section after implementation.

## Processing / Retry Model

- Reuse `ProcessingJob` concepts if implementation extends job type, but do not run lookup automatically from OCR.
- Lookup attempts should be idempotent by request fingerprint.
- User can cancel a running lookup UI flow; network cancellation records attempt state when feasible.
- Retry is manual after provider error/rate-limit/offline.
