# SeminarArc 0.4.x Transcription / Summary / Notion Plan

Status: readiness passed for local-safe production foundation

Updated: 2026-09-08

## Goal

`0.4.x` adds advanced post-seminar processing without weakening SeminarArc's local-first contract:

- transcript data model and review workflow；
- provider-independent `TranscriptionProvider` boundary；
- editable draft-only `SummaryProvider` boundary；
- Markdown/ZIP integration for transcript and draft summary；
- Notion-ready export contract while deferring public OAuth/backend live integration。

## Readiness Decision

`READINESS_PASS`

The first production milestone can proceed because the local-safe foundation does not require a paid account, private API key, recurring-cost backend, production signing, Google Play, or physical-device automation.

Live cloud transcription and live Notion publishing remain deferred provider paths until credentials/backend/OAuth decisions are made.

## Provider Decision

### Approved for first production milestone

1. `FakeTranscriptionProvider`
   - Used for ViewModel/repository/Worker/Emulator contract tests.
   - Produces deterministic timestamped segments from test fixtures.
   - No network or credentials.

2. `ManualTranscriptProvider`
   - Allows users to paste/edit transcript segments or import local text in a later UI.
   - Keeps transcript review useful even before live ASR is enabled.
   - No network or credentials.

3. `WhisperCppTranscriptionProvider` boundary
   - Implement interface, model availability state, job lifecycle and storage contract first.
   - Defer bundled model shipping until APK size/performance/license review is complete.
   - Android feasibility is plausible because `whisper.cpp` documents Android support and CPU/offline operation, but SeminarArc must benchmark model size, speed, heat and long-audio behavior before enabling it as default.

### Deferred provider paths

- OpenAI hosted Audio transcription: cloud upload and private API credential required; may support segment/word timestamps depending on response format/model, but needs user opt-in and backend or user-key decision.
- Alibaba Cloud Tingwu: cloud upload/account/credential required; supports speech transcription and speaker separation, but must stay optional and cannot become the core dependency.
- Android platform `RecognizerIntent` / speech recognizer: not suitable as the first durable long-recording provider because offline preference is implementation-dependent and designed around recognition intents/engine behavior rather than post-hoc seminar archive processing.
- Notion live publishing: official API supports OAuth and file upload, but public multi-user OAuth needs client secret/backend handling; first milestone should export Markdown-friendly Notion blocks locally instead of embedding private tokens in APK.

## Domain Contracts

### TranscriptionProvider

Inputs:

- `seminarId`
- `recordingId`
- app-owned audio file handle or asset reference
- language hint: `AUTO`, `ZH`, `EN`, `MIXED`
- timestamp granularity request: `SEGMENT`, optional `WORD`
- cancellation token

Outputs:

- provider id/version
- transcript metadata
- timestamped segments with start/end offsets
- speaker label if supported
- language if supported
- confidence/provenance where available
- retryability and readable errors

### SummaryProvider

Inputs must be user-selected:

- seminar metadata
- selected transcript windows
- selected OCR/key slides
- confirmed references
- user questions/notes

Outputs:

- editable draft fields only
- provenance mapping to selected inputs
- no overwrite of manual Seminar Brief
- no auto-confirmed claims

## Transcript / Timeline Association

- Transcript segments are anchored to `recordingId` and `startOffsetMs/endOffsetMs`.
- Photo/timeline association uses configurable windows around photo or event offset, default proposal:
  - before: 30 seconds
  - after: 90 seconds
- Timeline should show nearby transcript snippets, not the whole transcript.
- Reconstruction workspace may filter transcript windows by selected slide/key-slide.

## Privacy / Network Boundary

- Default `0.4.x` works without network.
- Any cloud transcription requires explicit user action and preflight preview:
  - provider;
  - selected recording or clip range;
  - estimated cost/limit when known;
  - deletion/cache semantics;
  - whether speaker diarization or word timestamps are requested.
- No app-owned commercial API secret in APK.
- User-provided keys or backend proxy require a later approved task.
- Logs must not contain transcript text, API token, full OCR corpus, audio path, or provider payload.

## UI Plan

Add completed-seminar workflow surfaces:

- Transcript status row in Seminar Detail.
- Transcript Review route:
  - processing state;
  - segment list by time;
  - segment edit/save;
  - jump to timeline/photo window;
  - retry/cancel failed jobs.
- Summary Draft route:
  - selected-input checklist;
  - draft generation state;
  - editable sections;
  - provenance chips;
  - export to Markdown/ZIP.
- Notion-ready export preview:
  - Markdown block layout;
  - media references;
  - no live Notion upload in first milestone.

Design constraints remain `Academic Archive`: list-first, quiet, seminar-scoped, no provider dashboard.
