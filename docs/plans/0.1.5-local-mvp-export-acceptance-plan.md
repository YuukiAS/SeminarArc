# SeminarArc 0.1.5 Local MVP Export And Acceptance Plan

Status: planned

Target version: `0.1.5`

## Goal

Close the local-first MVP by adding local Markdown/ZIP export, hardening the full capture-to-review flow, and aligning tests, docs, and CI with real behavior.

This is the final `0.1.x` milestone. It must not pull OCR, transcription, AI, Notion, ads, login, or cloud sync into the MVP.

## Inputs

- Completed `0.1.4` clip gate.
- `TODO.md` local-first and export rules.
- `docs/plans/0.1.x-mvp-implementation-plan.md` acceptance criteria.
- Current README, architecture, privacy docs, and design files.
- Complete local capture flow with recording/photos/timeline/clips.

## Scope

In scope:

- Markdown export for a single seminar.
- Optional ZIP export with `media/` relative links.
- Android share sheet.
- `ACTION_CREATE_DOCUMENT` export.
- Data cleanup tests.
- Permission/privacy/backup/recovery documentation.
- README screenshots and feature claims aligned with reality.
- CI hardening for build and unit tests.
- Final local MVP acceptance checklist.

Out of scope:

- Notion API implementation.
- Cloud upload.
- OCR/transcription/summary/provider processing.
- Cross-device sync.
- Ads, subscriptions, payments, analytics, or release signing.

## Export Contract

Markdown should include:

- Seminar title, speaker, affiliation, date/time, location.
- Abstract text.
- Abstract PDF reference if included.
- Recording summary and duration.
- Timeline events ordered by offset.
- Photos with relative paths when exported with media.
- Notes and questions.
- Marks and clip states.
- User-visible fallback text when a clip is not ready.

ZIP layout:

```text
<seminar-slug>/
  seminar.md
  media/
    abstract/
    photos/
    clips/
```

Rules:

- Exported paths must be relative.
- Unicode and LaTeX-like text must not be corrupted.
- Export must work offline.
- External exported copies are not deleted when the seminar is deleted; UI/docs must not imply otherwise.

## Work Breakdown

### 1. Export domain model

Define a domain export model that is independent of Android UI:

- `SeminarExportDocument`
- `ExportTimelineItem`
- `ExportMediaAsset`
- `ExportOptions`

Validation:

- JVM tests for mapping a seminar with recording/photos/notes/questions/marks/clips into export data.

### 2. Markdown renderer

Implement:

- Deterministic Markdown output.
- Stable ordering.
- Relative media links.
- Escaping for titles, notes, questions, and path text where needed.
- Golden tests for expected output.

Validation:

- Golden tests with English, Chinese, symbols, and LaTeX-like snippets.

### 3. ZIP/media export

Implement:

- Optional inclusion of abstract PDF.
- Optional inclusion of key/all photos depending on available tagging state.
- Optional inclusion of ready clips selected by user.
- Collision-safe media names.
- Missing-file handling that reports skipped files without failing unrelated content.

Validation:

- Tests for ZIP structure and missing media behavior.

### 4. Android export surfaces

Implement:

- `ACTION_CREATE_DOCUMENT` for Markdown and ZIP.
- Share sheet for exported Markdown/ZIP.
- UI progress and failure states.
- No cloud upload by default.

Accessibility:

- Export progress and success/failure are text-readable.
- Buttons have clear labels and content descriptions.

### 5. MVP acceptance and cleanup

Verify:

- Create seminar.
- Attach abstract PDF.
- Start seminar.
- Record, mark, capture photo, add question, add note.
- End seminar.
- Review all events in timeline.
- Play from event timestamps.
- Play ready clips or fallback correctly.
- Reopen app and verify persistence.
- Export Markdown/ZIP offline.
- Delete seminar and verify local records/files are cleaned.

### 6. Docs and CI

Update:

- `README.md` with true implemented features and commands.
- `docs/ARCHITECTURE.md` with final `0.1.x` architecture.
- `docs/PRIVACY.md` with local data, permissions, export semantics, and no-cloud default.
- CI workflow if tests need additional setup.

## Verification Gate

`0.1.5` is complete only when:

- `assembleDebug` succeeds in the documented environment.
- Unit tests pass.
- Room/export golden tests pass.
- Instrumentation smoke tests are either passing or explicitly documented with device/emulator requirements.
- README and docs do not claim future `0.2.x+` features as implemented.
- Full local acceptance scenario has been executed and recorded.

## Risks

- ZIP export over Android document APIs can be awkward; keep export logic domain-testable and isolate Android I/O.
- Large recordings/photos can make export slow; progress and cancellation may need follow-up.
- Exact screenshot/docs alignment should happen after final UI polish, not before.
