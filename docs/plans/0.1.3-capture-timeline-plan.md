# SeminarArc 0.1.3 Capture And Timeline Plan

Status: planned

Target version: `0.1.3`

## Goal

Complete the core offline seminar capture loop: record and/or photograph a live seminar, attach notes/questions/marks/photos to recoverable offsets, and review all events in one timeline.

This phase makes SeminarArc valuable without OCR, transcription, or AI.

## Inputs

- Completed `0.1.2` recording gate.
- `TODO.md` capture-first product principles.
- `docs/plans/0.1.x-mvp-implementation-plan.md`.
- `design/USER_FLOW.md`, `design/UI_SPEC.md`, `design/DESIGN_TOKENS.md`, and relevant state images.
- Existing Room schema and storage manager.
- Existing `PhotoCaptureGateway` interface.

## Scope

In scope:

- Live capture screen with `Record + Photos` and `Photos only` modes.
- CameraX quick slide capture.
- Last-photo feedback, undo/retake, and optional quick tags.
- `MARK`, `PHOTO`, `QUESTION`, and `NOTE` event creation.
- Offset calculation and recovery.
- Unified timeline page.
- `Play from here` for every event type when a recording exists.
- Photo-only flow without microphone permission.
- File ownership and deletion behavior for photos.

Out of scope:

- OCR, formula detection, image enhancement, and perspective correction.
- Full clip generation beyond creating mark events or pending records required by `0.1.4`.
- Transcription summaries.
- Notion or external export.
- Ads or cloud upload.

## Product Rules

- `Capture Slide` must be single-hand reachable and optimized for repeated shots.
- Capturing a photo should save immediately by default and show a short undo/retake affordance.
- Tagging is optional and must never block photo persistence.
- The live page must always show the current seminar identity.
- Timeline remains one chronological sequence, not separated photo/question/note tabs.
- Photo-only mode must support seminars where recording is not allowed or microphone permission is denied.

## Work Breakdown

### 1. Live capture mode model

Define UI/session states:

- `RecordAndPhotos`
- `PhotosOnly`
- `RecordingUnavailable`
- `PermissionDenied`
- `Recovering`

Behavior:

- If recording is active, offsets are based on recording start time and service truth.
- If photo-only, offsets are based on seminar session start time and clearly marked as session offsets.
- Session identity remains the same regardless of mode.

Validation:

- Unit tests for offset calculation in recording and photo-only modes.

### 2. CameraX capture pipeline

Implement:

- Camera preview/capture entry in the active session.
- App-private photo file creation under `files/seminars/<seminar-id>/photos/`.
- Orientation preservation.
- Immediate save.
- Last-photo thumbnail and saved feedback.
- Undo/retake that deletes rejected owned files.

Validation:

- Fake `PhotoCaptureGateway` tests for success, cancellation, failure, and retake cleanup.
- Instrumented smoke test where emulator/device camera is available.

### 3. Timeline event write path

Implement repository/use-case methods for:

- `MARK` event.
- `PHOTO` event with owned photo path.
- `QUESTION` event with text.
- `NOTE` event with text.

Rules:

- Every event must have `seminarId`.
- Every event must have an offset.
- A photo event must not exist without an owned photo path unless an explicit failure state is modeled.
- Deleting a photo event deletes its owned file.

Validation:

- DAO tests for chronological ordering.
- Repository tests for event creation and cleanup.

### 4. Live actions UI

Implement:

- High-emphasis `Mark Moment`.
- High-emphasis `Capture Slide`.
- Secondary `Add Question`.
- Secondary `Quick Note`.
- `End Seminar` with confirmation.
- Permission-denied and low-storage states.

Compose requirements:

- No nested card-heavy layout.
- Material/SeminarArc tokens only.
- Touch targets at least 48dp.
- `Recording`, `Photos only`, `Saved`, `Failed`, and `Permission denied` states use text, not color alone.
- Large-text layout cannot hide `Capture Slide` or `End Seminar`.

### 5. Unified timeline

Implement:

- Timeline screen route.
- Event rows ordered by offset.
- Photo thumbnail/preview affordance.
- Question and note editing entry points.
- Mark rows.
- File-missing state.
- `Play from here` for each event when a recording exists.
- Clear disabled/fallback text when no recording exists in photo-only seminars.

Validation:

- Compose UI tests for event visibility and actions.
- Unit tests for event sorting and display model mapping.

## Verification Gate

Do not start `0.1.4` until:

- A seminar can be captured in `Record + Photos` mode with marks, photos, notes, and questions.
- A seminar can be captured in `Photos only` mode without microphone permission.
- Timeline shows all event types under the same seminar.
- `Play from here` works or is clearly unavailable depending on recording state.
- Deleting photo events cleans owned files.
- No OCR/transcription UI is presented as working.

## Risks

- CameraX behavior varies by device; emulator validation is not enough for release.
- Rapid photo capture may create storage pressure and needs failure states.
- Offset consistency must be treated carefully across process death and service recovery.
