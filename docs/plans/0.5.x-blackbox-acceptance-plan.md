# SeminarArc 0.5.x Black-box Acceptance Plan

Status: active
Updated: 2026-09-13

## Goal

把当前 `v0.5.0-alpha.2` 之后的验收模式从“用户逐项手工点 UI”升级为：

1. JVM / Compose / instrumentation 继续验证内部逻辑；
2. Windows Emulator 上新增 package-level black-box acceptance；
3. 自动收集 screenshot / UI tree / scoped logcat 作为用户可读证据；
4. 自动发现并修复大部分 navigation / persistence / layout / export 问题；
5. 只把真实麦克风、真实相机、厂商 ROM 后台/锁屏和主观使用体验留给人工真机验收。

本计划不新增真实 ASR、LLM、Notion OAuth、Mathpix、Google Play 或其他新产品能力。

## Why

当前仓库已有较完整的 JVM、Compose instrumentation、Room migration、provider contract 和 Windows Emulator 回归，但这些多数从内部 test surface 驱动。用户已经能安装 `v0.5.0-alpha.2` 到真实 Android 手机，因此下一阶段更有价值的是验证“安装后的 app 是否能按真实用户路径工作”，而不是继续要求用户逐项点击现有功能。

## Test layers

### Layer 1 — Existing white/gray-box regression

继续保留：

- JVM unit tests；
- repository / use case / ViewModel tests；
- Room migration tests；
- Compose instrumentation；
- ML Kit / Bitmap / WorkManager emulator tests。

这些测试负责快速、精确定位内部回归，但不能单独替代真实用户流。

### Layer 2 — Package-level black-box acceptance

新增 Windows Emulator acceptance harness，把已安装 internal APK 视为黑盒应用。

允许使用：

- `adb -s <emulator>`；
- UI Automator accessibility tree；
- `adb shell input`；
- package manager / ActivityManager；
- screenshots；
- package-scoped logcat；
- Android 系统 picker/dialog。

原则：

- 用户路径必须通过可见 UI 完成；
- 不通过直接写 Room、repository injection 或 test-only navigation 来伪造用户完成状态；
- test setup 可以清理 Emulator 上的 internal package data，并准备 synthetic fixture；
- 所有设备写操作必须显式指定 emulator serial；
- GM1910 永远不参与。

## Acceptance scenario catalog

### B01 Fresh install / empty library

- 清理 internal app data；
- launch；
- library empty state；
- Create seminar CTA 可达；
- 无 crash / ANR。

### B02 Seminar CRUD / persistence

- 创建 seminar；
- required title validation；
- 填写 title / speaker / affiliation / date / location / abstract；
- 保存；
- 返回 library；
- 搜索；
- reopen；
- edit；
- force-stop / relaunch 后数据仍存在。

### B03 Session lifecycle

- start seminar；
- permission-denied UI；
- Emulator 可支持范围内的 permission-granted 流；
- NOTE / QUESTION / MARK；
- End Seminar；
- reopen completed seminar。

真实麦克风质量、CameraX 真实拍摄质量和 ROM 锁屏行为不在自动 PASS 定义内。

### B04 Reconstruction

使用 synthetic / emulator-safe media fixture：

- photo/asset 可达；
- enhancement；
- OCR；
- OCR edit；
- key slide；
- processing status；
- restart persistence。

### B05 Reference workflow

只使用固定公开 metadata fixture：

- evidence selection；
- query preview；
- candidate list；
- confirm / reject / reopen；
- Seminar Brief edit/save。

不得上传真实用户 seminar 内容。

### B06 Transcript / Summary local-safe flow

只测试当前真实能力：

- manual transcript import；
- segment edit；
- processing status；
- unavailable provider state；
- local summary draft edit/apply。

不把未配置真实 provider 判成失败。

### B07 Formula / research export

- formula region create；
- drag selection；
- saved region edit；
- manual LaTeX；
- provider unavailable status；
- formula result persistence；
- BibTeX / RIS / Markdown / ZIP / Notion-ready local export surface。

### B08 Recovery / cleanup

- force-stop / relaunch；
- durable state remains；
- synthetic seminar delete；
- library no longer shows deleted seminar；
- app remains healthy。

## Evidence contract

每个 scenario 至少记录：

- scenario id；
- PASS / FAIL / BLOCKED_BY_EMULATOR_LIMITATION；
- started/finished time；
- failed step；
- screenshot；
- UI tree；
- scoped crash/error logcat；
- visible symptom；
- app version / package / emulator serial。

推荐目录：

`private/blackbox-acceptance/<run-id>/`

大体积截图/log 不进入 Git；只提交：

- harness code；
- fixture definition；
- compact summary/result；
- 必要的小型 golden/reference 文件。

## Harness design

长期入口：

`scripts/run-blackbox-acceptance.ps1`

建议子目录：

`scripts/blackbox/`

包含：

- UI tree dump / summarize / node lookup；
- explicit emulator serial guard；
- process timeout / polling；
- screenshot/logcat capture；
- scenario runner；
- fixture helpers；
- summary renderer。

不要求引入 Appium/Maestro 等额外框架作为第一版依赖。优先使用现有 Android SDK/ADB/UI Automator 能力，减少环境复杂度。

## Timeout policy

避免再次出现长时间静默卡住：

- 普通 ADB/UI 操作：30–60 秒 hard timeout；
- 页面稳定等待：通常 <= 15 秒；
- 每 15–30 秒产生状态；
- Gradle/instrumentation 可更长，但必须定期有进度；
- timeout 后收集 screenshot + UI tree + logcat，再决定 retry；
- 禁止通过重启 ADB/USB/usbipd/WSL 解决 timeout。

## Real-world media corpus phase

B04-B07 的第一目标是验证真实用户工作流，必须保持 deterministic、可重复，不应因为等待用户提供真实 seminar 素材而阻塞。

在 B04-B07 flow acceptance 稳定后，增加独立的 **real-world media corpus robustness** 阶段，专门验证真实 seminar 条件下的输出质量，而不是基础 navigation/persistence。

### Corpus tiers

#### Tier A — committed deterministic fixtures

用于普通 regression：

- 自生成或明确允许再分发的图片/PDF；
- 覆盖中英文正文、标题/作者/DOI、公式、图表、长文本；
- fixture 小而稳定，可以安全进入公开 repo；
- 必须记录预期 OCR/reference/formula clue。

#### Tier B — user-provided private real seminar fixtures

这是最有价值的 robustness corpus，因为它真实包含：

- 投影透视；
- 远距离小字；
- 眩光/低亮度；
- 摩尔纹；
- motion blur；
- 裁切；
- 色偏；
- 复杂公式/图表/引用页。

规则：

- 默认放在 `private/real-world-fixtures/` 或等价本地目录，并加入 `.gitignore`；
- 不提交 public repo；
- 不上传第三方 provider；
- 用户可提供少量经过筛选的图片/PDF，不需要整场 seminar dump；
- 若素材包含未公开研究、参会者人脸、姓名或其他敏感内容，优先裁切/脱敏，或仅在本机使用。

建议第一批 5–10 张照片即可，覆盖：

1. title/overview slide；
2. reference-heavy slide；
3. dense text；
4. formula-heavy slide；
5. figure/chart；
6. 明显 skew/glare/blur 的困难样本。

PDF 建议 1–2 个，用于提供内容 ground truth、abstract/import/export 以及从 PDF 页面生成可控图片变体；不需要大量收集。

#### Tier C — public web corpus

只选明确公开且许可清楚的资源。

对不能明确再分发的公开网页/PDF：

- repo 只记录 source URL、access date、license/usage note、optional checksum；
- 本地测试任务按需下载到 ignored cache；
- 不把整份第三方 PDF/slide deck 直接提交进 public repo。

### CameraX realism

优先保持 black-box purity。Android Emulator 支持使用本地 image file 作为 camera source；在可行时，real-world fixture 应通过 Emulator camera -> app `Capture Slide` -> CameraX -> Reconstruction 链路进入，而不是直接写 Room 或注入 asset。

如果 image-backed camera 在当前 Emulator/AVD 上不稳定，可以把“真实图像质量 robustness”放在 provider/instrumentation corpus test 中，同时保留 B04 的 UI black-box flow 独立通过；不要为测试增加 production backdoor。

### Metrics / evidence

Real-world corpus 不应只看 PASS/FAIL，还应记录：

- OCR 是否完成；
- 可读文本召回的粗粒度质量；
- title/author/DOI clue 是否可提取；
- enhancement 前后可读性变化；
- formula region 是否可稳定框选；
- reference lookup 是否能从真实 clue 返回合理候选；
- crash / latency / memory / processing failure。

第一版不要求把 OCR quality 伪装成精确 benchmark；重点是发现真实 seminar 条件下明显退化或流程断点。

### Scheduling

当前顺序固定为：

1. B01/B02/B03/B08 foundation；
2. B04/B05/B06/B07 deterministic research-flow acceptance；
3. real-world media corpus robustness；
4. visual regression；
5. Monkey / multi-device；
6. major alpha / 0.9 再评估 Firebase Test Lab。

因此当前 B04-B07 task **不得等待用户提供真实素材**。用户可以之后提供真实照片/PDF，作为独立 corpus task 输入。

## Visual regression phase

在 black-box harness 稳定后再做，不与第一阶段强绑定。

目标覆盖：

- library empty/populated；
- New Seminar；
- Detail；
- Active Session；
- Reconstruction；
- Reference Review；
- Transcript Review；
- Formula region UI。

配置至少：

- normal phone；
- smaller phone；
- normal font scale；
- enlarged font scale；
- long text / empty / error state。

Golden 更新必须显式批准，禁止测试失败时自动接受新截图。

## Exploratory stress phase

在核心 E2E 稳定后：

- package-scoped Monkey；
- fixed seed；
- crash logcat；
- seed + event count 写入 result；
- crash 必须可重放。

## Multi-device phase

在不影响现有 Windows Emulator/GM1910 隔离的前提下，评估：

- API 36 current phone；
- smaller-screen profile；
- 一个仍受 minSdk/target support 的旧 API profile。

可以评估 Gradle managed devices，但不得让任何 managed-device 配置接触 protected physical device。

## Firebase Test Lab readiness

只做后续 major-alpha / 0.9 readiness，不作为当前 harness blocker。

后续可评估：

- Robo test；
- small physical device matrix；
- screenshot/video/log evidence；
- cost/quota；
- Firebase project/account boundary。

没有现成 Firebase 配置时，不自动创建付费资源。

## Human-only acceptance

自动 harness 完成后，人工验收应压缩到：

1. 真实手机麦克风录音质量；
2. CameraX 拍真实投影/PPT 的质量和方向；
3. 锁屏/后台/厂商 ROM 对长录音影响；
4. 一次低风险真实 seminar 的连续操作手感；
5. 主观 UI/UX 判断。

用户不再负责逐项证明普通按钮、CRUD、navigation、export、persistence 是否工作。

## Release policy

Black-box acceptance 不要求每次普通 commit 发版。

如果 harness 发现并修复 P0/P1 或明显 dogfood blocker，可准备 `0.5.1-alpha.*`；否则只更新 tests/harness，不创建无意义 Release。

## Suggested task split

1. `0.5.x_blackbox_acceptance_harness_task.md` — harness foundation + B01/B02/B03/B08。
2. `0.5.x_blackbox_research_flows_task.md` — B04/B05/B06/B07 deterministic research-flow acceptance。
3. `0.5.x_real_world_media_corpus_task.md` — user/private + public/open fixtures，真实 seminar 图像/PDF robustness。
4. `0.5.x_visual_regression_task.md` — screenshot/golden + font/screen matrix。
5. `0.5.x_exploratory_stress_task.md` — Monkey + optional multi-device。
6. major alpha / 0.9: Firebase Test Lab readiness/optional execution。
