# SeminarArc 0.5.x Formula / Research Export Plan

Status: readiness passed for local-safe production foundation

Updated: 2026-09-08

## Goal

`0.5.x` adds formula-aware research reconstruction without weakening SeminarArc's local-first contract:

- user-selected formula regions on seminar-owned slide photos;
- provider-independent formula OCR boundary;
- editable LaTeX results with confidence and provenance;
- deterministic BibTeX/RIS export from confirmed references;
- Markdown/ZIP/Notion-ready export polish for formulas and research notes.

## Readiness Decision

`READINESS_PASS`

The first production milestone can proceed because local formula region persistence, manual LaTeX editing, fake-provider contract tests, and BibTeX/RIS export do not require paid API credentials, backend deployment, external upload, production signing, Google Play, or physical-device automation.

Live Mathpix and other cloud provider paths remain deferred until credential/backend/user-key policy is approved.

## Provider Decision

### Approved for first production milestone

1. `ManualFormulaProvider`
   - Lets users paste or edit LaTeX for a selected formula region.
   - No network, account, model, or credential.
   - Keeps formula export useful before live OCR is enabled.

2. `FakeFormulaOcrProvider`
   - Used for repository/use case/ViewModel/Worker tests.
   - Produces deterministic LaTeX, confidence, provider id/version, and provenance from fixtures.
   - No network or credentials.

3. `FormulaOcrProvider` boundary
   - Define input/output/cancel/retry/idempotency behavior before any live provider.
   - Persist selected region, source asset id, result state, LaTeX text, confidence, provider metadata, and user edit state.

### Deferred provider paths

- Mathpix: strong candidate for high-accuracy formula OCR, but authenticated API access, billing, and API-key secrecy are required. The Android APK must not embed app-owned Mathpix credentials. A future implementation needs either a backend-issued short-lived token flow or explicit user-owned key policy.
- PaddleOCR formula recognition: plausible self-hosted/local candidate with formula recognition modules/pipeline and multiple model sizes, but Android packaging, model storage, performance, heat, memory, dependency/license review, and model-source policy need separate validation.
- pix2tex / LaTeX-OCR: useful open-source/self-hosted candidate for fixtures and desktop/server evaluation. Public pretrained weights need separate license approval or replacement weights before APK bundling.

## UX Contract

- Users explicitly choose a formula region from a seminar-owned photo before OCR runs.
- Region selection should preserve the original photo and store only normalized crop coordinates plus a preview/crop derived asset when needed.
- Formula OCR is never run automatically on every photo.
- Result UI must show LaTeX source, provider id/version, confidence band, provenance link to source photo/region, edited state, and retry/cancel controls for queued/running/failed provider work.
- Manual edit is always available and remains the canonical user-corrected formula text.

## Domain Contracts

### FormulaOcrProvider

Input:

- `seminarId`
- `regionId`
- source photo asset id
- normalized crop rectangle
- optional cropped local file handle
- language/context hint
- cancellation token

Output:

- provider id/version
- result state
- LaTeX text
- optional MathML/Markdown text if provider returns it
- confidence score/band
- retryability
- readable error
- provenance payload without raw secret or full private file path

### ResearchExportRenderer

The first implementation can be deterministic and local:

- BibTeX from confirmed references only.
- RIS from confirmed references only.
- Stable cite keys derived from first author/year/title with collision suffixes.
- DOI, URL, venue, title, authors, year and note fields mapped from existing confirmed reference metadata.
- Pending/rejected candidates are excluded.
- Missing fields produce valid but visibly incomplete records rather than fabricated metadata.

## Export Integration

Markdown/ZIP/Notion-ready exports should eventually include:

- formula region list;
- edited LaTeX source;
- confidence/provenance;
- links back to source slide photo paths inside the ZIP when available;
- BibTeX/RIS files under stable research export paths such as `<seminar-slug>/references/references.bib` and `<seminar-slug>/references/references.ris`.

## Privacy / Network Boundary

- Default `0.5.x` works without network.
- Any cloud formula OCR requires explicit user action and preflight preview: provider, selected image region only, estimated cost/limit when known, deletion/cache semantics, and retained provider payload scope.
- No app-owned commercial API secret in APK.
- User-provided keys or backend proxy require a later approved task.
- Logs must not contain full LaTeX notes, API token, raw provider payload, or app-private absolute file paths.

## Testing Plan

- `MIGRATION_6_7` schema migration.
- formula region insert/update/delete cascade.
- formula result provider success/failure/cancel/retry/idempotency.
- manual LaTeX edit preserves provider provenance.
- BibTeX/RIS renderer golden tests, including DOI, URL, missing fields, Unicode titles, author escaping, cite-key collisions, and excluded pending/rejected candidates.

Emulator:

- formula region selection UI states.
- formula result edit/retry/cancel states.
- export surface includes formulas and research files.
- old `0.1.x/0.2.x/0.3.x/0.4.x` regression.

Live provider smoke:

- Not part of ordinary CI.
- Uses public/test fixture images only.
- Requires explicit provider credential/backend decision before real cloud calls.
