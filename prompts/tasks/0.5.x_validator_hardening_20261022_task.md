## 实施顺序与有界代表案例

1. 为每个现有 runner 记录真实参数、输出和调用者，先抽出/复用纯函数可测试部分，不先启动设备。校准至少覆盖：正常读到非空 OCR、真实空内容、标签包裹文本导致旧观察器读空；缺照片应未证，不能让 B04/B07 虚假通过。
2. 冻结同候选 good/bad/missing/unchanged：保存按钮有反馈但数据不落盘；photos-only 错误调用前台服务；导出 ZIP 结构有而关键内容缺；权限对话框未退；系统 picker 未完成；不同 API 输入映射；同秒两次 run 不覆盖证据；跳过动态探针；错误 APK/serial。使用隔离样本或可逆测试缝，禁止把故障注入生产包。
3. 保留现有 9/9 媒体数据声明的完整性，但私有样本不可用时只记录该语料未复验，先完成公开/合成的读取器校准。合成图不能冒充真实拍照、真实照片 OCR 质量或硬件音质。
4. 首条动态纵向链必须在获权的 disposable emulator 上运行 B02/B03；再按相关性运行 B04–B08 与小屏/字体等既有矩阵。进入设备前回读脚本是否 install/clear-state/force-stop；只有 task-owned 测试包和明确可清理的测试状态可获批准后执行。
5. 当前参数形状（值须来自本轮预检）为 `powershell -NoProfile -File scripts/run-blackbox-acceptance.ps1 -Serial <observed-emulator> -ApkPath <exact-candidate-apk> -Scenarios B02,B03 -SkipBuild`；`-SkipInstall` 只能在已安装候选 hash/身份匹配时用。不要把该示例当设备授权。先用现有 Gradle wrapper 跑受影响 JVM test/build/lint，再进入合法设备阶梯；不要从 WSL 使用混杂 Windows SDK。
6. 把 B01–B08 原生 summary、全局结果和限制接回既有正常流程，执行者必须消费逐项失败。新建的校准案例也进入正常可重复命令；不能只留未接线脚本。
7. 独立 GPT Work 仍用 `prompts/gpt-work/SEMINARARC_GPT_WORK_ACCEPTANCE_PARENT.md` 单 Parent 与既有 candidate/scenario/evidence/result 合同。普通黑盒 reviewer 只看真实产品和中性事实，不暴露源码、Room、producer QA、golden 或旧结论给它找标准答案。准备就绪回执不是审查通过。
