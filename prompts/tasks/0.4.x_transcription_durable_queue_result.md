# 0.4.x Transcription Durable Queue Result

## Status

Implemented.

## Changes

- Added `ProcessingWorkScheduler.enqueueTranscription(recordingId, languageHint)`.
- `WorkManagerProcessingWorkScheduler` now validates completed recordings, resolves the recording asset, creates/reuses a durable `TRANSCRIPTION` job, and enqueues unique WorkManager work.
- `ProcessingWorker` now handles `TRANSCRIPTION` by reading recording id/language hint input and delegating to `RunTranscriptionForRecordingUseCase`.
- Retry/recovery can rebuild transcription work from the job input asset's `sourceRecordingId`.
- Added `UnavailableTranscriptionProvider` and Hilt binding as the safe production default until a real ASR provider is explicitly configured.
- Added JVM coverage for the default unavailable provider's non-retryable failure contract.
- `SUMMARY_DRAFT` and `NOTION_EXPORT_PREP` remain deliberately unexecuted by the generic worker.

## Privacy / Scope Boundary

- The default transcription provider does not upload audio and does not fake a transcript.
- Failed unavailable-provider jobs are recorded locally as provider-unavailable failures.
- No live ASR provider, cloud upload, SummaryProvider scheduling, Notion OAuth/upload, backend, private credential, or recurring-cost service was added.
