# 0.4.x Transcript Timeline Windows Result

## Status

Implemented.

## Changes

- Added `BuildTranscriptTimelineWindowsUseCase`.
- Added `TranscriptTimelineWindowInput`, `TranscriptTimelineWindow`, and `TranscriptTimelineWindowResult`.
- The use case validates transcript ownership and requires `TranscriptState.READY`.
- Timeline windows are derived from configurable before/after offsets around `PHOTO`, `MARK`, `QUESTION`, and `NOTE` events by default.
- Transcript segments are matched by interval overlap so long segments spanning the event are preserved.
- When an event has a `recordingId`, segments from other recordings are excluded while manual/unknown recording segments remain eligible.
- Photo assets are linked first by `sourceTimelineEventId`, then by timeline `photoPath`.
- Preview text is normalized and bounded for future UI/export consumption.

## Privacy / Scope Boundary

- This is a local derivation over existing Room/domain data only.
- No media, transcript text, OCR corpus, summary prompt, reference metadata, or user notes are uploaded.
- No live ASR, LLM summary provider, Notion OAuth/upload, backend, credential, or recurring-cost service was added.
