# Phase A：External Metadata Provider Research

必须联网查 **官方文档/官方条款**，不能只靠模型记忆或博客。

至少研究：

## Crossref

核对：

- Works API 查询能力；
- title / author / bibliographic / DOI query；
- filters；
- cursor/pagination；
- rate/polite pool / mailto 建议；
- User-Agent / contact 要求；
- attribution / terms；
- 返回字段稳定性；
- DOI、title、author、published、container-title 等字段；
- 商业 app 使用是否需要 key；
- 缓存 metadata 是否允许/建议；
- API availability/error behavior。

## OpenAlex

核对：

- Works search / filter；
- DOI lookup；
- title/full-text search能力边界；
- authorships / publication year / source / concepts/topics / datasets 等 metadata；
- API key / polite pool / rate limit 当前政策；
- attribution / license；
- commercial use；
- snapshot/API 差异；
- caching / local persistence 合理边界。

## Semantic Scholar Academic Graph API

核对：

- paper search / title / DOI lookup；
- fields；
- API key 与 rate limit；
- terms / attribution / commercial use；
- 是否适合作为第一版 default provider、fallback provider 或暂缓。

## 可选 provider

如果有明确价值，可补：

- Europe PMC（生命医学）
- DataCite（数据集/非 Crossref DOI）

但不要为了 provider 数量而扩大 scope。

### Provider research 输出

形成比较表，至少包含：

- coverage；
- DOI lookup；
- title/author search；
- dataset/venue metadata；
- authentication；
- rate limit；
- attribution/license；
- commercial suitability；
- privacy exposure；
- offline fallback；
- first-version recommendation。

必须给出明确结论，例如：

- primary provider；
- secondary/fallback；
- deferred provider；

并解释为什么。

# Phase B：Evidence Extraction Design

设计如何从当前已有本地材料构造 reference lookup evidence。

允许输入：

- 用户明确选择的 OCR text；
- KEY_SLIDE / REFERENCE tag photo OCR；
- seminar metadata；
- 用户手工输入的 title / DOI / author clue；
- question/note 中用户主动选择用于查文献的文字。

不要默认把整个 seminar 所有 OCR text 自动上传给 provider。

设计至少包括：

## DOI extraction

- DOI regex / normalization；
- `doi:` / URL form 清理；
- OCR 常见字符错误；
- exact DOI lookup 优先级。

## Bibliographic clue extraction

无需 LLM 的第一版可使用：

- title-like lines；
- author-like lines；
- year；
- venue/journal/conference；
- method/dataset clue；
- slide labels such as References / Related Work。

明确哪些可以 deterministic heuristic，哪些暂时只让用户手动确认。

本阶段禁止偷偷加入 LLM extraction。

# Phase C：Candidate Matching / Ranking Design

必须定义透明、可测试、无需 LLM 的第一版 candidate scoring。

考虑但不限于：

- exact DOI match：最高置信；
- normalized title similarity；
- author overlap；
- publication year proximity；
- venue match；
- provider cross-confirmation；
- OCR evidence quality/confidence；
- query type（DOI > exact title > noisy OCR）。

输出一个明确 scoring contract。

不要只写“综合评分”。必须说明：

- score components；
- normalization；
- threshold；
- tie handling；
- exact DOI override；
- low-confidence behavior。

第一版 UI 不要给用户伪精确的 `93.7% certainty`，除非 score 真有可解释概率意义。

建议使用：

- High confidence candidate；
- Possible candidate；
- Needs review；

或其他不制造统计含义的表述。

# Phase D：Room / Domain Evolution Design

基于当前真实 Room v3，设计 `0.3.x` 所需最小 schema。

重点评估：

## ReferenceCandidateEntity

候选字段至少考虑：

- seminarId；
- provider；
- providerWorkId；
- DOI；
- title；
- authors；
- year；
- venue/source；
- canonical metadata JSON（如有必要）；
- query/evidence provenance；
- ranking score / match reason；
- `PENDING / CONFIRMED / REJECTED`；
- timestamps。

## ReferenceEvidence / lookup query

判断是否需要独立表记录：

- 来源 asset/OCR result；
- query text；
- extracted DOI/title/author clues；
- provider query；
- lookup timestamp。

不要为了“数据库漂亮”过度拆表。

## SeminarBriefEntity

设计 app-owned editable brief，而不是 provider/AI output。

第一版字段至少评估：

- background/context；
- core question；
- methods；
- main results；
- key takeaways；
- unresolved questions；
- follow-up actions；
- user notes；
- confirmed reference links；
- key-slide links；
- updatedAt。

明确哪些字段来自用户编辑，哪些可以由已有 local data 提示填充，但不能由尚不存在的 AI 自动声称完成。

## Migration

设计 v3 -> 下一 version 的显式 Room migration：

- 不破坏 v3 assets/jobs/OCR/tags；
- 不 destructive；
- migration instrumentation strategy；
- old data reopen；
- rollback/failure protection。

本 task 只设计，不实现 migration。

# Phase E：Network / Privacy / Terms Model

0.3.x 是 SeminarArc 第一次真正需要向外部 metadata service 发请求，因此必须重新定义 privacy boundary。

明确：

- 用户必须显式触发 lookup；
- 默认发送的最小字段；
- exact DOI lookup 与 OCR-title search 的 privacy 差异；
- 不发送照片二进制；
- 不发送录音；
- 不发送整个 seminar archive；
- provider endpoint / query string 可能暴露的内容；
- metadata cache 保留策略；
- 删除 seminar 后候选 metadata 如何清理；
- offline 时 UI 如何表现；
- timeout / retry / rate-limit / 429；
- provider unavailable 时不阻塞本地 Reconstruction。

更新 `docs/PRIVACY.md` 的 planning section，但不要把未实现能力写成已上线。

- candidate list；

- candidate detail；
- duplicate DOI handling；
- no-result / rate-limit / offline / provider error；
- Seminar Brief 编辑界面；
- confirmed references 如何进入 Brief；
- Brief 如何进入现有 Markdown/ZIP export。

继续遵循 `Academic Archive`，不要做成搜索引擎 dashboard。
