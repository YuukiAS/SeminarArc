# 0.1.x Local MVP Device Acceptance Resume Task

## 目标

恢复此前因 WSL ADB 设备不可见而停止的 `0.1.x Local MVP Completion Master Goal`。

当前代码/headless 线已经推进到 `0.1.5`。本 task 只补齐仍缺失的**非破坏性真机 E2E 证据**，发现真实 app bug 时允许修复、重新构建、单步安装并复测。

不要重新实现已经完成的 `0.1.3` / `0.1.4` / `0.1.5` 功能，不进入 `0.2.x`。

## 当前恢复背景

- 先前真机：serial `8cc54656`，`GM1910` / OnePlus 7 Pro。
- 2026-08-30 曾在 `connectedDebugAndroidTest` instrumentation APK 安装阶段后发生连接安全事件：WSL ADB 丢失 serial，Windows `usbipd` 设备退回 `Shared (forced)`。
- 用户已亲自在 Windows PowerShell 恢复 usbipd attach；当前截图显示 `GM1910` 已重新为 `Attached`。
- **这次恢复成功不构成未来可以冒险掉线的理由。保持真机连接的优先级高于完成 E2E。**

## 绝对设备安全规则

### 1. 禁止 connected / instrumentation 自动安装链

本 task **明确禁止**：

- `connectedDebugAndroidTest`
- `connectedAndroidTest`
- 任何 `connected*AndroidTest`
- 任何 `device*AndroidTest`
- Gradle 自动 instrumentation APK 安装/runner 链
- batch device tests
- Managed Device 对该物理真机的等价流程

不要为了 migration instrumentation test、coverage 或 UI test 再运行这些命令。

### 2. 禁止任何连接恢复/重置命令

严禁：

- `adb disconnect`
- `adb reconnect`
- `adb kill-server`
- `adb reboot`
- `adb tcpip`
- `adb usb`
- `adb pair`
- `adb connect`
- USB mode 修改
- `usbipd attach/detach/bind/unbind`
- usbipd service restart
- `wsl --shutdown`
- USB detach/unbind
- 任何等价操作

如果设备再次从 ADB 消失：**立即停止整个 task，不做任何自动恢复。**

### 3. ADB 只在 WSL 使用

设备已经 attach 给 WSL 后：

- 不调用 Windows 侧 `adb.exe`；
- 不尝试 Windows/WSL 双端 ADB；
- 统一使用：

`/home/yuukias/Android/Sdk/platform-tools/adb`

除 `adb devices -l` 外，所有真机命令显式指定：

`-s 8cc54656`

但开始时必须实际复核 serial；如 serial 不一致，停止，不盲用历史值。

### 4. 单步动作 + preflight/postflight

每个会改变 app/device 状态的动作前：

`adb devices -l`

确认目标 serial 唯一且状态为 `device`。

动作后立刻再次：

`adb devices -l`

只有仍为同一 serial / `device` 才可继续下一步。

不得把多个真机写操作串成一个长 shell command。

不得并行运行 Gradle、ADB、scrcpy 或第二个设备自动化流程。

### 5. 不删除、不移动、不清数据

禁止：

- uninstall
- clear app data
- 删除/移动已有用户媒体、文件或数据库
- 删除已有 seminar
- 覆盖已有外部导出文件

本轮产生的 app-owned 测试 seminar、录音、照片和 clip 可以保留在设备上。

如验证 export，需要使用新的唯一测试文件名，不覆盖现有文件，并保留测试导出副本。

删除/cleanup E2E 不在本 task 授权范围内；最终必须标记 `NOT_TESTED_REQUIRES_HUMAN_APPROVAL`，不得偷偷执行。

## 第一阶段：连接 preflight

只做 WSL 侧检查：

1. `/home/yuukias/Android/Sdk/platform-tools/adb devices -l`
2. 确认 serial、model 和状态。
3. 使用 `adb -s <serial> shell getprop` 读取必要的只读设备属性。
4. 使用 EchoSelect harness `check-lock-state` 检查锁屏状态。

如果设备不是 `device`：立即停止，不恢复连接。

不要运行 `lsusb` 安装或系统包变更；本 task 不需要它。

## 第二阶段：确认设备上 app build

先通过只读 package 信息确认 SeminarArc 是否已安装以及当前 version/build。

如果设备上的 app 已经对应当前 `main` 所需版本，则不要为了“保险”重复安装。

只有确定必须安装当前最新 APK 时，才允许：

1. 先 headless 构建：`./gradlew testDebugUnitTest assembleDebug lintDebug`
2. preflight `adb devices -l`
3. 单独执行一次：
   `/home/yuukias/Android/Sdk/platform-tools/adb -s 8cc54656 install -r app/build/outputs/apk/debug/app-debug.apk`
4. 立即 postflight `adb devices -l`

若 install 期间/之后设备消失：立即停止，不重试。

禁止 Gradle `installDebug` 替代该受控单步安装。

## 第三阶段：非破坏性 Local MVP E2E

创建一个**全新、名称唯一**的测试 seminar，例如带当前时间戳，避免修改已有 seminar。

使用真实 UI 和现有 app 交互完成：

1. 创建 seminar；
2. 填写最小 metadata；
3. 如已有可安全使用的测试 PDF，可以 attach；如果没有，不要为了该步骤操作私人文件，可记录 abstract PDF 为单独 evidence gap；
4. Start Seminar；
5. 确认真实 foreground microphone recording；
6. 确认 notification；
7. Capture Slide 至少一张；
8. Mark Moment；
9. Add Question；
10. Quick Note；
11. Home / background 后确认 recording 继续；
12. 使用现有安全 harness 进行锁屏/解锁验证，不改变 USB transport；
13. 从 notification 返回对应 Active Session；
14. End Seminar；
15. 确认 foreground service/active notification 正常消失；
16. 确认 `.m4a` app-private 文件存在；
17. Detail full recording Play / Pause / Seek；
18. 打开 unified timeline，确认 PHOTO / MARK / QUESTION / NOTE 排序与内容；
19. 验证 `Play from here`；
20. 等待/检查 clip 状态，验证 READY clip playback；若真实生成失败，验证 FAILED/PENDING 的 full-recording fallback 和 retry 状态，不得假装 READY；
21. Home 后重新进入 app，验证 seminar/timeline 持久化；
22. 验证 Markdown export；
23. 验证 ZIP export；
24. 检查导出内容/结构与相对媒体路径。

### 允许的交互方式

- EchoSelect secret-safe unlock harness；
- `adb -s ... shell input ...` 的普通 UI 输入；
- `uiautomator dump`；
- `screencap`；
- `dumpsys`；
- `logcat`；
- `run-as com.yuukias.seminararc` 对 app-private 测试数据做**只读**检查；
- 单个受控 scrcpy 会话，但不得使用 `--tcpip`，不得与其他设备流程并行。

不得使用 instrumentation runner 替代上述 E2E。

## 第四阶段：发现 bug 时的处理

如果真机 E2E 发现 app bug：

1. 保存非敏感证据；
2. postflight 确认 ADB 仍在线；
3. 停止真机交互；
4. 在代码侧修复；
5. 运行 JVM/build/lint；
6. commit + push；
7. 如确有必要，再按“单步 `adb install -r` + pre/postflight”重新安装一次；
8. 只复测相关失败场景和必要回归。

不要因为一个 UI bug 连续反复安装 APK。

## 停止条件

以下任一发生必须立刻停止：

- `adb devices -l` 不再显示同一 serial 为 `device`；
- 设备进入 `offline` / `unauthorized`；
- usbipd/WSL 可见性异常；
- 任何命令似乎触发 USB/ADB transport 重枚举；
- 需要 uninstall/clear/delete/move 才能继续；
- 需要 connected/instrumentation test 才能继续；
- 需要执行任何连接恢复命令；
- 发现可能损害用户已有设备内容的操作。

发生时只记录证据并停止，不自行恢复。
