# 0.4.x Summary Durable Queue Task

## Objective

Connect the transcript review summary action to a durable local `SUMMARY_DRAFT` processing queue without enabling a live LLM provider, cloud upload, Notion OAuth/upload, backend deployment, private credential, or recurring-cost service.

## Scope

- Add a bounded durable payload for summary draft input so selected transcript segments can survive process death and WorkManager retry/recovery.
- Persist that payload on `processing_jobs` with an explicit Room migration and checked-in schema.
- Enqueue `SUMMARY_DRAFT` work from `TranscriptReviewViewModel` for the selected transcript and its current segments.
- Teach `ProcessingWorker` to decode the payload and call `DraftSummaryForSeminarUseCase`.
- Add a safe default `UnavailableSummaryProvider` that records provider-unavailable failure instead of faking a summary.
- Keep retryability semantics explicit for invalid local input versus provider failure.

## Out of Scope

- No live summary provider.
- No provider picker.
- No transcript, reference, note, photo, recording, export, log, or app-private data upload.
- No Notion OAuth/upload.
- No backend.
- No connected Android test or APK installation while Windows ADB can see protected physical device serial `8cc54656`.
