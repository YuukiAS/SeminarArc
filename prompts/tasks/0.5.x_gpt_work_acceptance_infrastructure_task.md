# 0.5.x GPT Work 独立 Android 黑盒验收基础设施

## 目标

在不执行正式 GPT Work campaign、不要求用户验收、不操作受保护真机的前提下，冻结当前本地 0.5.x candidate，建立可重复的 synthetic acceptance state、Windows Emulator 启动/重置/验证工具、真实 Android UI 自动化预检、证据合同、P01–P08 独立审查提示和一份自包含、可直接交给 GPT Work 的最终 Parent。

## 允许动作

- 读取当前 Git、QA closeout、black-box/visual/stress harness 与 Emulator inventory。
- 构建并冻结当前 local candidate，记录 commit、APK SHA-256、package、version、signer、Room schema、AVD 和 Android API。
- 创建 non-sensitive realistic synthetic academic fixture、task-owned ignored acceptance state/evidence/output。
- 创建或复用 task-owned Emulator/AVD；所有设备写操作必须显式限定到 `emulator-*`。
- 安装或配置本机 acceptance-only Appium/UiAutomator2 工具，并以真实可见 App UI 完成 hierarchy、locator、click、input、screenshot、Back 和 relaunch preflight。
- 修改 `docs/operations/gpt-work-acceptance/`、`prompts/gpt-work/`、acceptance-only scripts、必要的 UI testability/accessibility semantics、README/TODO/roadmap/changelog 与本 task result。
- 运行静态 delivery gate、focused build/test 和 sacrificial UI-control dry-run；提交 task-owned tracked 文件。
- 尝试使用受限 helper 发布当前分支；若 GitHub authentication 仍不可用，记录 `BLOCKED_BY_GITHUB_AUTH`，不向用户索要 credential。

## 禁止动作

- 不启动正式 GPT Work campaign，不把 producer preflight 冒充独立产品审查。
- 不要求用户安装 APK、逐页点击或现在验收。
- 不操作 GM1910 / `8cc54656`；不运行 unscoped connected/device task；不执行 ADB/USB/usbipd/WSL transport reset。
- 不读取、上传或暴露 private real seminar 内容；不把真实 corpus 用作 GPT Work 默认 fixture。
- 不接入云 ASR、LLM、Notion、Mathpix、付费 API、production signing、Google Play、公开发布或新产品能力。
- 不让 GPT Work 读 repo、源码、Room、app-private state、producer QA 结果或 golden；不得通过 test API/直接写内部状态完成被审业务动作。
- 不修改或提交无关的 `Microsoft/Windows/PowerShell/ModuleAnalysisCache`。
- 不 reset、rebase、force-push 或丢弃本地已完成 QA commit。

## 验收门槛

1. exact candidate identity 完整且可重验，同一 campaign 绑定同一 APK hash。
2. launcher、reset、verify 可从批准的 synthetic scenario 启动 visible App，且永不目标化 physical device。
3. S00–S08 来源、角色映射、恢复方法和禁止绕过动作明确；fixture 无隐私、无工程 placeholder。
4. 至少一种语义 UI automation 路径实际完成 Emulator/package/hierarchy/control/click/input/screenshot/Back/relaunch preflight。
5. P01–P08 提示完整，Parent 内联黑盒、severity、result、evidence、serial/reset、tool-failure 与 stop contract，无 placeholder、secret、producer-result contamination。
6. `verify-gpt-work-acceptance.ps1` 的 candidate/environment/scenario/prompt/dry-run gate 全部通过后，才可写 `PARENT_DELIVERY_GATE = PASS` 与 `READY_TO_PASTE_PARENT = YES`。
7. 最终状态仍为 `GPT_WORK_EXECUTED = NO`、`READY_FOR_USER_REVIEW = NO`、`USER_ACTION_REQUIRED_NOW = NO`。
