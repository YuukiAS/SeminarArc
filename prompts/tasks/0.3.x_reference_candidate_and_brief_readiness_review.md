# 0.3.x Reference Candidate + Seminar Brief Readiness Review

## 结论

`READINESS_PASS` 结论成立，可以进入 `0.3.x` production implementation。

本轮 planning 的核心方向正确：

- Crossref 作为论文 bibliographic / DOI-first primary provider；
- OpenAlex 用于 fallback 与 cross-confirmation；
- DataCite 仅在 dataset/software/non-Crossref DOI 证据下 targeted fallback；
- Semantic Scholar 因当前 API license 对商业产品存在额外限制而 deferred；
- lookup 必须用户显式触发并先显示 query preview；
- 第一版 extraction/ranking 不引入 LLM；
- candidate 必须 review-first，不能自动确认；
- Seminar Brief 是 app-owned、用户编辑的文档，而不是 AI 输出；
- `0.3.x` 不下载论文 PDF、不做转写/LLM/Notion/formula OCR。

这些决策与 SeminarArc 的 local-first、可解释、低风险产品原则一致。

## 值得保留的设计

### 1. Evidence provenance 是一等公民

单独设计 `ReferenceEvidenceEntity` 是必要的。reference lookup 的可信度来自“用户选了哪段 OCR / note / DOI clue”，而不是来自 provider 自己的 relevance score。Candidate Review 应能回看 evidence 与 provider metadata 的对应关系。

### 2. 匹配分数不冒充概率

100 分 contract 可以作为 deterministic ranking heuristic，但 UI 只显示 `HIGH_CONFIDENCE / POSSIBLE_MATCH / NEEDS_REVIEW`，不显示类似 `93.7% certainty` 的伪概率。这一点应保持。

### 3. Query preview + opt-in network

0.3.x 是第一次把 seminar-derived text 发送到外部服务。用户应能在请求前看到实际要发送的 DOI/title/author/year clue 和 provider。照片、录音、完整 OCR corpus、完整 timeline 不应上传。

### 4. Seminar Brief 不依赖尚不存在的 AI

第一版 prose 字段全部由用户编辑；只允许 prefill 可验证的 local facts / confirmed references / key slides / selected questions。这能避免 0.3.x 提前变成一个不可审查的“自动总结”功能。

## Production 前需要收紧的 5 个细节

这些不是 readiness blocker，但应在第一批 production task 中修正后再冻结 v4 schema/network contract。

### A. Candidate 与 provider observation 应分离

当前 plan 的 `ReferenceCandidateEntity` 同时包含单个 `provider/providerWorkId`，又要求 Crossref/OpenAlex/DataCite 多 provider 合并、cross-confirmation 和 provenance 保留。这两个语义有冲突。

建议 v4 使用：

- `ReferenceCandidateEntity`：app-owned canonical candidate；
- `ReferenceCandidateSourceEntity`：一条 provider observation，例如 Crossref/OpenAlex/DataCite 的 provider id、provider work id、返回的 DOI/title/year/source、selected payload subset、provider-native relevance（若有）。

这样：

- 一个 candidate 可以由多个 provider 支持；
- cross-confirmation count 可测试；
- provider metadata 不必挤进一个 JSON；
- 后续 provider refresh 不会覆盖 canonical user-reviewed truth；
- Semantic Scholar 若未来获批也可自然加入。

`providerPayloadJson` 不应默认保存完整 provider response。

### B. 不默认缓存 Crossref abstract / 大块 raw payload

Crossref 官方说明大部分 bibliographic metadata 可自由复用，但 abstract 仍可能受 publisher/author copyright 约束。0.3.x 只需要 title/authors/year/venue/DOI/type/landing/license/OA 等最小 metadata。

因此 provider cache 默认保存 normalized selected fields；完整 raw payload 只在确有诊断需要且 terms/privacy 明确时再考虑，不作为 v4 source of truth。

### C. Matcher 必须版本化

当前 35/20/10/... 的 100 分 score 是第一版 heuristic，不是校准概率，未来一定可能调整。

建议至少保存：

- `matcherVersion`，如 `reference-match-v1`；
- component breakdown 或可重建的 `matchReasons`；
- score/confidence band。

不要让未来算法改权重后无法解释旧 candidate 为什么是 High/Possible。

### D. OCR 修复 DOI 不能直接享受 exact DOI override

从 OCR 中直接提取、仅做 URL/标点/case normalization 的 DOI 可以走 exact DOI lookup。

但是 `O/0`、`I/l/1`、broken slash/line-wrap 等属于 speculative repair。应：

1. 保留原始 evidence；
2. 生成 repair variants；
3. lookup variant；
4. 只有 provider 返回结果且 title/author/year 与 selected evidence 足够一致时，才能提升到 High confidence；
5. 不允许“修过字符串 -> provider 有这个 DOI -> 自动 100 分确认”。

### E. Client-side API credentials 必须进一步收紧

Crossref / DataCite public retrieval 不需要 secret。

OpenAlex 当前允许 keyless basic use；免费 API key 会提高预算，但个人 key 同时是 OpenAlex account sign-in credential。因此第一版 Android client 不得硬编码开发者 OpenAlex key。默认采用 keyless fallback + 本地节流；若未来需要稳定/大规模 keyed usage，应通过后端或经明确设计的 credential 模型进入后续版本。

Semantic Scholar 继续 deferred；当前普通 API license 明确限制在非商业研究/教育用途，商业/其他用途需要 expanded license。

## Rate-limit 修正

Crossref production limiter 不能简单按“public 5 rps / polite 10 rps”应用到所有 endpoint。

从 2025-12-01 起，Crossref 对 list/query request 的限制低于 single DOI request：public list query 约 1 rps、polite list query约 3 rps，而 single record 可以更高。实现应：

- exact DOI 与 bibliographic search 分开限流；
- 优先读取 response rate-limit headers；
- 429 honor retry/backoff；
- 不在用户一次 lookup 中并发轰炸多个 provider。

## 推荐 production 顺序

### Phase 1 — v4 schema/domain + fake providers

先冻结 schema，不联网：

- canonical candidate + provider source observation；
- evidence / lookup attempt；
- Seminar Brief + joins；
- `MIGRATION_3_4`；
- matcherVersion；
- fake provider contract tests。

### Phase 2 — deterministic extraction / rank / dedup

纯 Kotlin：

- DOI raw extraction + normalization + repair variants；
- bibliographic clue extraction；
- candidate scoring；
- confidence bands；
- cross-provider merge；
- golden fixtures，尤其 noisy OCR / conflicting evidence。

### Phase 3 — network/provider layer

按顺序实现：

1. Crossref exact DOI + bibliographic lookup；
2. OpenAlex keyless fallback/cross-confirmation；
3. DataCite targeted DOI/query fallback。

要求最小 outbound data、query preview、timeouts、offline、429、manual retry、cache。

Live API smoke 必须 opt-in，不进入普通 CI。

### Phase 4 — candidate orchestration / repository

把 evidence -> lookup attempt -> provider -> merge/rank -> candidate persistence 串成 app-owned flow；重复 request fingerprint 幂等。

### Phase 5 — Candidate Review UI

Reconstruction -> select evidence -> query preview -> results -> match reasons -> confirm/reject/reopen。

### Phase 6 — Seminar Brief + export

用户编辑 Brief；confirmed references / key slides 关联进入 Brief；Markdown/ZIP renderer 加可选 Brief section 和 reference section。

### Phase 7 — Windows Emulator closeout

- `MIGRATION_3_4` connected；
- fake-network Candidate Review 全状态 UI；
- offline/rate-limit/provider error；
- Brief edit/save/export；
- 0.1.x / 0.2.x full regression；
- 少量 opt-in live Crossref/OpenAlex/DataCite smoke，但不依赖 live API 作为 CI PASS 条件。
