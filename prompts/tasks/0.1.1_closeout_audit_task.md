# Task: SeminarArc 0.1.1 Closeout Audit

## Goal

Turn the current `0.1.1-dev` foundation into a verified baseline before any `0.1.2` foreground recording or CameraX work begins.

## Required Inputs

Read these files before implementation or audit conclusions:

- `AGENTS.md`
- `prompts/AGENT_RULES.md`
- `docs/plans/0.1.1-closeout-plan.md`
- `TODO.md`
- `README.md`
- `docs/ARCHITECTURE.md`
- `docs/plans/0.1.x-mvp-implementation-plan.md`
- `docs/plans/0.1.x-mvp-execution-batch-01.md`
- `design/README.md`
- `design/UI_SPEC.md`
- `design/DESIGN_TOKENS.md`
- `.agents/skills/android-lead/SKILL.md`
- `.agents/skills/compose-expert/SKILL.md`

Read supporting Android/Compose reference files as needed for architecture, Room/repository, build, testing, UI, and accessibility review.

## Allowed Actions

- Run local shell commands needed for build, unit tests, repository inspection, and static audit.
- Read source, Gradle, CI, docs, and design files.
- Make documentation fixes.
- Make small, low-risk code or test fixes that are clearly inside `0.1.1` closeout scope.
- Write the result to `prompts/tasks/0.1.1_closeout_audit_result.md`.

## Forbidden Actions

- Do not use network access.
- Do not upload files, logs, build artifacts, or results.
- Do not commit or push.
- Do not delete user data.
- Do not implement foreground recording service, CameraX, active timeline capture, clip generation, OCR, transcription, AI, Notion, cloud sync, login, ads, subscription, or payment features.
- Do not add new schema for future `0.2.x` Research Reconstruction.

## Audit Scope

Verify:

- Gradle wrapper files are present and usable.
- `compileSdk`, `targetSdk`, and dependency versions resolve in the local environment.
- `./gradlew assembleDebug` status is known.
- `./gradlew testDebugUnitTest` status is known.
- `.github/workflows/android.yml` runs meaningful build/test commands.
- Room entities, DAO queries, foreign keys, and repositories support the `0.1.x` capture model.
- Repository and storage operations orchestrate database rows and app-owned files consistently.
- UI layers do not read Room directly.
- Seminar list remains list-first and Room-backed.
- Editor creates/edits real seminars and manages abstract PDFs through repository/storage paths.
- Detail screen clearly labels future `0.1.2` behavior without pretending recording is implemented.
- Delete confirmation and cleanup describe or handle owned seminar assets.
- Search, filters, favorite, rating, and abstract attachment behavior match README claims.
- Existing Compose UI follows Material 3/SeminarArc token direction and avoids fake completion paths.
- Large-text and TalkBack-critical controls have reasonable 48dp targets and labels.
- `README.md`, `docs/ARCHITECTURE.md`, `docs/PRIVACY.md`, and `design/README.md` describe actual current behavior accurately.

## Expected Result

Write `prompts/tasks/0.1.1_closeout_audit_result.md` with:

- Execution summary.
- Files read.
- Files modified.
- Commands run and exit status.
- Build/test results.
- Findings with file references.
- Diff summary.
- Required human approvals, if any.
- Remaining issues.
- A gate decision: whether the repository can enter `0.1.2` foreground recording work.
