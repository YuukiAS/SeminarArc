# 0.4.x Transcription Durable Queue Task

## Objective

Wire `TRANSCRIPTION` into the existing WorkManager-backed durable processing queue while keeping live ASR provider execution safely unavailable until a real provider is selected and approved.

## Scope

- Add a scheduler API for enqueueing transcription from a completed recording.
- Create durable `TRANSCRIPTION` `ProcessingJob` rows using the recording asset as input.
- Enqueue unique WorkManager requests carrying recording id and language hint.
- Let `ProcessingWorker` execute transcription work through `RunTranscriptionForRecordingUseCase`.
- Preserve retry/recovery behavior for queued or interrupted transcription jobs.
- Add a production-safe default `TranscriptionProvider` that reports unavailable instead of uploading or faking success.

## Out of Scope

- No live ASR engine.
- No cloud upload.
- No SummaryProvider scheduling.
- No Notion OAuth/upload.
- No connected Android test or APK installation while Windows ADB can see protected physical device serial `8cc54656`.

## Verification

- Run headless Gradle verification with D-drive local homes:
  - `.\gradlew.bat --no-daemon testDebugUnitTest compileDebugAndroidTestKotlin`
  - `.\gradlew.bat --no-daemon lintDebug assembleInternal`
- Verify the internal APK with `apksigner`.
