## Absolute physical-device prohibition

The only allowed unscoped ADB command is read-only inventory:

`adb devices -l`

For every other ADB command, explicit serial is mandatory:

`-s emulator-5554`

Never execute any command with `-s 8cc54656`.

Never execute:

- `adb kill-server`
- `adb start-server` for transport recovery
- `adb reconnect`
- `adb disconnect`
- `adb usb`
- `adb tcpip`
- `adb pair`
- `adb connect`
- `usbipd attach/detach/bind/unbind`
- WSL shutdown/restart
- Windows service reset intended to alter device transport
- physical install/shell/input/scrcpy/instrumentation

Do not attempt to make `8cc54656` disappear from the Windows inventory. If it remains `unauthorized` or `offline`, simply ignore it.

## Critical change from old closeout

Do **not** run:

- `connectedDebugAndroidTest`
- `connectedAndroidTest`
- any Gradle `connected*AndroidTest` / `device*AndroidTest` task that may enumerate visible devices

when physical serial is present in Windows ADB inventory.

Instead, run an explicit-emulator-only instrumentation path.

## Phase 3 — Explicit serial instrumentation

Using only commands of the form:

`D:\Android\Sdk\platform-tools\adb.exe -s emulator-5554 ...`

perform:

1. Emulator wake/unlock only if needed.
2. Install/replace the intended debug app APK on the Emulator.
3. Install/replace the corresponding androidTest APK on the Emulator.
4. Invoke the exact instrumentation runner explicitly with `am instrument` on `emulator-5554`.
5. Capture exit/result output and test counts.

The goal is to execute the same instrumentation coverage that the ordinary connected suite is intended to provide, but without unscoped Gradle device enumeration.

If test sharding/filtering is needed, keep every install/shell/instrumentation command explicitly serial-scoped.

At minimum require coverage for current migration/UI/regression tests, including the 0.5 formula-region/formula-queue/export surfaces plus retained 0.1/0.2/0.3/0.4 suites that exist in the current androidTest APK.

If some existing Gradle-only reporting convention cannot be reproduced exactly, use JUnit/instrumentation result output as the acceptance evidence and explain the equivalence. Do not fall back to unscoped connected Gradle tasks.

## Phase 5 — Timeout / polling discipline

Do not allow another opaque hour-long wait.

Requirements:

- poll external processes every ~15-30 seconds;
- print/record progress each polling interval;
- ordinary ADB/package commands: hard timeout around 30-60 seconds;
- Gradle/instrumentation may have a longer total budget, but no more than ~60 seconds of unexplained silence;
- use a finite total timeout appropriate to the suite (for example 10-15 minutes, adjusted only with evidence);
- on timeout, terminate only the current Emulator-side process when safe, collect output, diagnose, and retry if appropriate;
- never “fix a timeout” by resetting ADB/USB/usbipd/WSL transport.
