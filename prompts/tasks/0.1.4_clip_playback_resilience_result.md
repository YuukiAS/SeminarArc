# 0.1.4 Clip Playback Resilience Result

## 完成内容

- 实现 `ClipIntervalCalculator`：默认 pre-roll `60_000ms`、post-roll `90_000ms`，支持 start clamp、completed duration clamp、post-roll 未满足时的 not-ready 语义。
- 扩展 `AudioClipEntity` / Room schema，新增 `retryCount`；实现 `ClipDao` 查询、插入、状态更新和按 source event 删除。
- 实现 `ClipRepository` / `ClipRepositoryImpl`：MARK event 自动创建 `PENDING` clip，支持 `PROCESSING`、`READY`、`FAILED`、retry、删除 clip-owned 文件。
- 实现 `ClipGenerationWorker` 和 `WorkManagerClipWorkScheduler`：worker 以 clip ID 作为输入，重读 Room clip/recording，验证 completed recording 和 source file 后生成 clip。
- 实现 `AndroidM4aClipGenerator`：使用 Android `MediaExtractor` / `MediaMuxer` 从本地 `.m4a` 录音裁剪真实 clip artifact，不伪造 `READY`。
- Timeline UI 扩展 clip 状态：`READY` 且 clip 文件可读才显示 `Play clip`；`FAILED` 显示 retry；所有非 ready 状态保留完整录音 `Play from here` fallback。

## 验证

- `./gradlew testDebugUnitTest assembleDebug lintDebug`：通过。
- 覆盖新增 JVM 测试：clip interval 边界、pending clip 创建、retry count、clip-owned 文件删除路径。

## 未执行的外部验收

- 本轮没有执行真机/设备上的 WorkManager + MediaMuxer 实录音裁剪 smoke test。
- 原因：当前线程遵守“先不要求真机验收”和“不允许断开真机或者删除移动任何真机内容”的边界；没有进行设备解锁、安装、录音、拍照、裁剪或文件删除动作。
- 因此 0.1.4 的代码和 headless gate 已完成，但真实设备上的 clip artifact 生成仍需后续非破坏性验收。
