# 0.1.2 Recording State 与 One-active-seminar Invariant

## 目标

本任务只完成 `0.1.2` 第一阶段：建立可持久化、可测试的 seminar session 状态模型，并在 repository/domain 层保证任意时刻最多一场 `ACTIVE` seminar。

## 范围

- 审查当前 Room entity、DAO、repository、ViewModel、navigation 与测试代码。
- 确认当前 schema version 1 是否足够表达本阶段状态。
- 补齐本阶段需要的 DAO 查询与 mutation。
- 在 domain 层定义非 Boolean 的 start session 结果语义。
- 在 repository 层集中实现 one-active invariant 与事务边界。
- 增加 unit tests 覆盖 success、same-active、different-active、stale/conflict、数据库事实和 failure path。

## 明确不做

- 不实现真实 `ForegroundService`。
- 不接入 `MediaRecorder`、`AudioRecord`、Media3、CameraX 或通知。
- 不创建真实录音文件，不生成 clip，不采集 timeline。
- 不加入 OCR、转写、AI、Notion、云同步、登录、广告、订阅或支付。
- 不进行大规模 UI redesign。

## 验收条件

- `startSeminarSession` 一类 domain API 能区分：
  - 成功开始新 session；
  - 当前 seminar 已经 active；
  - 另一个 seminar 已 active；
  - stale / inconsistent active state；
  - 明确失败。
- UI 与 ViewModel 不直接拼装 one-active invariant。
- 状态转换在 repository/domain 层通过 Room transaction runner 执行。
- 没有不必要的 Room schema bump；若发生 schema 变化，必须有显式 migration。
- 新增或完善 JVM unit tests 覆盖本任务要求。
- 离线运行：
  - `./gradlew --offline assembleDebug`
  - `./gradlew --offline testDebugUnitTest`
