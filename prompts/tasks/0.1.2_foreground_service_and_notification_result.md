# 0.1.2 Foreground Service、Notification 与真实本地录音结果

## 最终架构

- UI：`SeminarDetailScreen` 只负责请求运行时权限并触发 `SeminarDetailViewModel`。
- Use case：`StartSeminarRecordingUseCase` 统一执行 `startSeminarSession(seminarId)`、麦克风权限检查、通知权限软状态读取和 foreground service 启动。
- Service：`SeminarRecordingService` 接收 `START` / `STOP` command，拥有 foreground lifecycle。
- Coordinator：`RecordingServiceCoordinator` 持有当前进程内 live recorder，处理 duplicate start、start/stop/failure compensation。
- Recorder backend：`AndroidMediaRecorderController` 使用 Android `MediaRecorder` 录制 microphone audio。
- Durable truth：`RecordingRepositoryImpl` 通过 Room 维护 `RecordingEntity` 状态。
- Notification：`SeminarRecordingNotificationFactory` 创建 channel 和 ongoing notification。

## Manifest / Permissions

已在 `AndroidManifest.xml` 中声明：

- `RECORD_AUDIO`
- `POST_NOTIFICATIONS`
- `FOREGROUND_SERVICE`
- `FOREGROUND_SERVICE_MICROPHONE`
- `SeminarRecordingService`
  - `android:exported="false"`
  - `android:foregroundServiceType="microphone"`

本阶段按 Android Developers 当前文档实现：

- `RECORD_AUDIO` 是 microphone FGS 的 runtime prerequisite。
- `POST_NOTIFICATIONS` 不是启动 foreground service 的硬前提，但 denial 会作为可观察结果返回 UI。
- Service 启动前和 service 内都会复查 `RECORD_AUDIO`。

## Foreground Service 行为

- `ACTION_START`：
  - 无 `seminarId` 时停止。
  - 无 `RECORD_AUDIO` 时停止，不创建 recording row。
  - 创建 notification channel。
  - 尽快用 starting notification promote foreground。
  - 调用 `RecordingServiceCoordinator.start(seminarId)`。
  - 成功后更新为 seminar title 的 ongoing recording notification。
- `ACTION_STOP`：
  - 调用 coordinator stop。
  - stop foreground 并 stop self。
- Service 使用稳定 notification ID：`2101`。
- 当前未添加 notification Stop action，避免在状态转换未完整设计前扩大交互面。

## Recorder Backend

- Backend：`AndroidMediaRecorderController`。
- API：Android `MediaRecorder`。
- Audio source：`MediaRecorder.AudioSource.MIC`。
- Output format：`MediaRecorder.OutputFormat.MPEG_4`。
- Encoder：`MediaRecorder.AudioEncoder.AAC`。
- Bitrate：`128000`。
- Sample rate：`44100`。
- Extension：`.m4a`。
- `stop()` 抛异常时返回 failure，并释放 recorder，不写 completed。

## Recording File Ownership

- Recording file 由 `MediaStorageManager.createRecordingOutputFile(seminarId, startedAt)` 创建。
- 路径位于 app-private seminar-owned directory：
  - `files/seminars/<seminar-id>/recordings/recording-<utc timestamp>.m4a`
- Room 保存相对路径，例如：
  - `seminars/12/recordings/recording-20260813-080000-000.m4a`
- 未使用的 start attempt file 会在 repository 拒绝时清理。

## RecordingEntity 状态转换

- Start success：
  - 插入 `RecordingEntity(state = RECORDING, startedAt, filePath)`。
  - recorder 成功启动后 service 进入 in-memory `Recording` state。
- Start failure：
  - 如果 row 已创建，则写 `FAILED`、`endedAt`、`errorMessage`。
  - 不写 completed。
- Stop success：
  - recorder stop 返回 duration。
  - Room 条件更新 `RECORDING -> COMPLETED`，写 `endedAt` 和 `durationMs`。
- Stop/finalize failure：
  - 写 `FAILED` 和 `errorMessage`。
  - 不伪装 completed。
- Process restart recovery：
  - `RecordingRecoveryInitializer` 在 app process start 时把遗留 `RECORDING` rows 标记为 `FAILED`，暴露 recorder 已死的 stale durable state。

## Transaction / Compensation Strategy

SQLite、filesystem 和 `MediaRecorder` 不能形成跨资源 ACID transaction。本阶段采用显式补偿：

- DB begin 前先创建目标 file path；若 session invalid 或 duplicate durable row，清理本次未使用 file。
- DB row 创建成功但 recorder start 失败：把 row 写为 `FAILED`。
- Recorder stop 成功但 Room completed 条件更新失败：尝试写 `FAILED`，不声称 completed。
- Recorder stop 抛异常：release recorder，写 `FAILED`。
- App process restart 后仍为 `RECORDING` 的 rows：标记 `FAILED`，保留诊断信息。

## Notification 行为

- Channel：`seminar_recording`。
- Channel importance：`IMPORTANCE_LOW`。
- Notification：ongoing、service category、stable notification ID。
- Content：
  - Starting：`SeminarArc is starting recording`。
  - Recording：`SeminarArc is recording` + seminar title。
- PendingIntent 返回 `MainActivity`，不会创建第二个 session。
- 本阶段不每秒更新 timer notification，避免不必要的 notification churn。

## 已知限制

- 没有真机或 emulator 麦克风验收。
- 当前详情页只是最小启动入口，不是完整 Live Capture UI。
- 没有 notification stop action。
- 没有 Media3 full recording playback UI。
- 没有 timeline capture、CameraX、clip generation 或 playback fallback。
- 没有处理电话中断、音频焦点、蓝牙麦克风、超长录音空间不足等设备级边界。

## 真机验收尚缺什么

- 授权 `RECORD_AUDIO` 后从详情页启动 service，确认系统麦克风指示和 notification。
- 后台/锁屏期间保持录音。
- 返回 app 后发送 STOP command 并确认 `.m4a` 文件可播放。
- 拒绝 `POST_NOTIFICATIONS` 后确认 foreground service 行为符合目标 Android 版本系统展示。
- 进程被杀后确认遗留 `RECORDING` row 被标记为 `FAILED`。
