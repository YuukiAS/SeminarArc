# 0.4.x Summary Draft Use Case Task

## Objective

Add the first provider-independent summary draft orchestration layer for `0.4.x`.

## Scope

- Build a domain use case that creates summary draft requests from:
  - seminar metadata,
  - user-selected transcript segments,
  - confirmed reference titles,
  - selected key-slide captions,
  - manual or existing brief notes.
- Persist provider output to `summary_drafts` through `TranscriptRepository`.
- Persist provider failures as `FAILED` drafts with retryable provenance boundaries.
- Keep `SeminarBrief` user-authored content untouched.
- Add focused JVM tests with a fake `SummaryProvider`.

## Out of Scope

- No live LLM or cloud summary provider.
- No Notion OAuth/upload.
- No UI route for summary generation yet.
- No connected device test or APK installation while Windows ADB can see protected physical device serial `8cc54656`.

## Verification

- Run headless Gradle verification with D-drive local homes:
  - `.\gradlew.bat --no-daemon testDebugUnitTest compileDebugAndroidTestKotlin`
  - `.\gradlew.bat --no-daemon lintDebug assembleInternal`
- Verify the internal APK with `apksigner`.
