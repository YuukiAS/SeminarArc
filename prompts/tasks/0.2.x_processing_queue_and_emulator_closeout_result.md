## Processing queue

- 新增 `ProcessingWorkScheduler`。
- 新增 `WorkManagerProcessingWorkScheduler`，以 unique work `seminararc-processing-<jobId>` 调度 OCR/enhancement。
- 新增 `ProcessingWorker`，worker input 使用 job ID，并在执行时重新读取 Room / app-private storage。
- `QUEUED`：UI/use case 先创建 durable job row，再 enqueue WorkManager。
- `RUNNING`：worker 执行 provider 前写入。
- `SUCCEEDED`：OCR 写 `ocr_results`，enhancement 写 `PHOTO_ENHANCED` derived asset，再写 job success。
- `FAILED`：写 readable error、retryable flag，并清理 partial enhancement output。
- `CANCELLED`：scheduler cancel unique work，并把 durable job 标记为 cancelled。
- duplicate：同一 input asset + operation 的 active `QUEUED/RUNNING` job 复用，不无限创建。
- retry：retryable failed/cancelled job 重新置为 `QUEUED` 并用 WorkManager `REPLACE` 重排。
- recovery：app start 调用 `recoverProcessingJobs()`，把 orphan `RUNNING` 还原为 `QUEUED` 并重排 queued/running work。
