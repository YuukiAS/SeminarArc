# 0.4.x Summary Draft Use Case Result

## Status

Implemented.

## Changes

- Added `DraftSummaryForSeminarUseCase`.
- The use case builds a `SummaryRequest` from seminar metadata, user-selected transcript windows, confirmed reference titles, key-slide captions, and manual or existing brief notes.
- The input fingerprint is deterministic over the resolved transcript windows and selected context.
- Provider success is persisted as a `READY` `SummaryDraft`.
- Provider failure is persisted as a `FAILED` `SummaryDraft` with the provider message and without modifying `SeminarBrief`.
- Added JVM tests covering:
  - selected transcript window routing,
  - reference/key-slide context inclusion,
  - required user segment selection,
  - failure persistence with existing brief notes,
  - no `SeminarBrief` overwrite.

## Privacy / Scope Boundary

- No live ASR, LLM, cloud summary, Notion OAuth/upload, backend, private API credential, or recurring-cost service was added.
- The summary use case depends on a `SummaryProvider` contract only; current tests use a fake provider.
- User-authored `SeminarBrief` content remains separate from generated `summary_drafts`.
