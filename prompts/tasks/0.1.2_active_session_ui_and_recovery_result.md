# 0.1.2 Active Session UI、Recovery 与 End Seminar 结果

## 执行摘要

- 新增正式 `ActiveSessionRoute`、`ActiveSessionViewModel` 和 `ActiveSessionScreen`。
- Detail 页 `DRAFT` 显示 `Start seminar`，`ACTIVE` 显示 `Resume seminar`，正常启动/恢复后导航 Active Session，`COMPLETED` 不再显示 start/resume。
- Notification 点击通过 `MainActivity` intent extra 返回对应 Active Session，不创建第二个 session。
- 修复 startup recovery race：process start 先捕获 stale `RECORDING` IDs，再只 fail 这些 IDs；`StartSeminarRecordingUseCase` 会等待 recovery gate 后再创建新 recording。
- 修复 durable `RECORDING` 与 live recorder 混淆：当前进程没有 live runtime 时，Room 遗留 `RECORDING` row 返回 `StaleRecording` / `RecoveryRequired`，不再返回普通 `AlreadyRunning` 或显示 recording notification。
- 新增 `RecordingRuntimeStateProvider` / `RecordingRuntimeController` 抽象，UI 只观察 runtime state provider，不直接依赖 concrete Android `Service`。
- 新增 `EndSeminarUseCase`，先停止/finalize recorder，再条件化完成 seminar 并写 `sessionEndedAt`。

## Recovery correctness

- `RecordingRecoveryInitializer` 现在维护 waitable startup recovery gate。
- `startProcessRecovery()` 在 app process start 触发恢复；`awaitProcessRecovery()` 供 start flow 等待。
- 恢复过程先调用 `RecordingRepository.getOpenRecordingIds()` 捕获启动前 stale IDs，再调用 `failRecordings(recordingIds = staleIds, ...)`。
- 新进程中新创建的 recording 不会被延迟执行的 startup recovery 误杀，因为启动新 recording 前必须等待 gate 完成，且 fail 操作只处理捕获到的 ID 集合。

## Stale durable recording 语义

- `RecordingRepositoryImpl.beginRecordingForActiveSeminar(...)` 遇到当前 seminar 已有 durable `RECORDING` row 时返回 `BeginRecordingResult.StaleRecording`。
- `RecordingServiceCoordinator` 只有在 `activeRuntime != null` 时才返回 `AlreadyRunning`。
- `activeRuntime == null` 且 Room 有 `RECORDING` row 时，coordinator 设置 `RecordingServiceState.RecoveryRequired` 并返回 `RecordingServiceCommandResult.RecoveryRequired`。
- Service 遇到 recovery required 会停止 foreground，而不是展示正在录音 notification。

## Service teardown 策略

- `SeminarRecordingService.onDestroy()` 不再假设销毁来自正常 STOP。
- 正常 STOP 完成后设置 `normalStopCompleted = true`，避免 onDestroy 二次 fail。
- 异常销毁时调用 `RecordingRuntimeController.abandonActiveRecording(...)`，release recorder，并把当前 live recording 标记 `FAILED`。
- Process death 没有可靠 onDestroy 时，后续 process-start recovery 继续处理遗留 durable `RECORDING` row。

## Active Session navigation 与 UI state

- `Seminar Detail -> Active Session` 已接入正式 route。
- start/resume 成功后进入 Active Session。
- 如果另一场 seminar 已 active，Detail flow 导航到已有 active seminar。
- Active Session UI state 使用 sealed 类型：`Loading`、`Recording`、`Ending`、`PermissionDenied`、`RecoveryRequired`、`Failed`、`Completed`。
- Recovery UI 覆盖 stale interrupted recording、active session 缺 start time、multiple active conflict 等状态。
- `Capture Slide`、`Mark Moment`、`Add Question`、`Quick Note` 只保留视觉位置并 disabled，未写 fake timeline event。
- 未实现 waveform、pause/resume、CameraX、Media3 playback、clip 或 timeline capture。

## Timer 计算方式

- Active Session timer 使用 `RecordingSession.startedAt`；starting 状态回退到 durable `SeminarDetail.sessionStartedAt`。
- UI 通过 Compose 本地 `LaunchedEffect` 每秒 tick 重新计算显示。
- Tick 不是 durable truth，不会每秒写 Room。
- 该策略依赖 wall clock；如果用户手动大幅调整系统时间，显示 elapsed 可能跳变，但 Activity/ViewModel recreation 不会从 `00:00` 错误重置。

## End Seminar 状态转换

- `EndSeminarUseCase` 是正式业务入口，ViewModel 不直接拼接 stop service、update recording、update seminar 和 navigation。
- live recorder 存在时：
  1. 调用 `RecordingRuntimeController.stopActiveRecording()`。
  2. Coordinator stop 成功后把 `RecordingEntity(RECORDING)` 条件更新为 `COMPLETED`，写 `durationMs`。
  3. 再调用 `SeminarRepository.completeActiveSeminar(seminarId)`。
  4. Repository 条件更新 seminar `ACTIVE -> COMPLETED`，写 `sessionEndedAt`。
  5. 请求 service stop 移除 foreground notification。
- stop/finalize 失败时，coordinator 把 recording 标记 `FAILED`，`EndSeminarUseCase` 返回 `StopFailed`，seminar 不被标记 `COMPLETED`。
- 无 live recorder 的 stale active seminar end flow 只 fail 当前 seminar 的 open recording rows，然后尝试完成 seminar。

## 新增测试

- `RecordingServiceCoordinatorTest`
  - durable `RECORDING` + no live runtime -> `RecoveryRequired`，不启动 recorder。
  - in-process duplicate START -> `AlreadyRunning`，不创建第二个 recorder/row。
  - abnormal runtime abandon -> release recorder，Room 标记 `FAILED`。
  - startup recovery 只 fail 捕获的 stale IDs，不包含捕获后出现的新 row。
- `ActiveSessionViewModelTest`
  - live runtime -> `Recording` UI state。
  - ViewModel recreation -> 从 durable `startedAt` 恢复 timer source。
  - another active seminar -> recovery/conflict state。
  - stale active + failed recording -> recovery state，可 resume/end。
  - `RECORD_AUDIO` denied -> `PermissionDenied` state。
- `EndSeminarUseCaseTest`
  - normal stop 后再 complete seminar。
  - stop failure 不 complete seminar。
  - no live recorder 时只 fail 当前 seminar open rows。
  - duplicate/already completed end 返回明确结果。
- `StartSeminarRecordingUseCaseTest`
  - completed seminar 不能重新 start flow。
