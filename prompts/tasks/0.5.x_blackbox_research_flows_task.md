`D:\Code\SeminarArc-emulator`

```powershell
D:\Android\Sdk\platform-tools\adb.exe devices -l
```

如果 inventory 同时看到 protected physical serial，沿用仓库批准的 mixed-inventory explicit-emulator lane：

## Black-box contract

B04-B07 的 acceptance execution 仍把安装后的 internal APK 当成黑盒。

允许：

- UI Automator / accessibility tree；
- `adb shell input`；
- screenshot；
- scoped logcat；
- Android system picker/dialog；
- package manager / ActivityManager；
- emulator-local synthetic/public fixture。

禁止：

- 直接写 Room 伪造用户流程；
- repository/use-case injection 伪造状态；
- test-only navigation shortcut；
- production hidden backdoor；
- 上传用户真实 seminar 数据。

Test setup 可以操作 disposable Emulator 的 app-private state / external test files，但必须通过真实用户可见入口让 app 接收或产生业务数据。

# B04 — Reconstruction

目标：验证从真实用户可见入口获得 photo asset 后，Reconstruction 主路径可用。

至少覆盖：

1. 通过现有用户流程获得至少一个 photo asset；优先使用 Emulator CameraX / app 自身 `Capture Slide`。
2. 从 seminar detail / timeline 进入 Reconstruction workspace。
3. photo preview 可见。
4. image enhancement action 可触发，并出现正确 processing state / result。
5. OCR action 可触发，状态正常结束或给出可解释失败。
6. OCR result 如存在，可通过 UI 编辑并保存。
7. key-slide toggle 可操作并持久化。
8. force-stop / relaunch 后 asset / OCR edit / key-slide 等可恢复状态仍在。

### Deterministic OCR fixture rule

不要为了 exact-text OCR assertion 引入 production backdoor。

如果当前 Emulator CameraX 无法提供稳定、可控的文字画面：

- 仍完成 photo capture / enhancement / OCR job lifecycle / OCR edit surface / persistence 黑盒验收；
- exact recognized text 可标记为 `BLOCKED_BY_EMULATOR_FIXTURE_LIMITATION`；
- 既有 ML Kit instrumentation 的 deterministic OCR 内容测试仍作为底层 evidence；
- 不因此把整个 B04 判 FAIL。

如果能通过现有系统 UI / emulator-safe fixture 产生 deterministic image，则可以增加 exact OCR assertion。

# B05 — Reference workflow

允许网络，但只使用固定公开 bibliographic fixture；不得使用用户真实 seminar/OCR。

优先使用当前 UI 已支持的 manual `USER_INPUT` evidence，使 B05 不依赖 B04 OCR 文本是否 deterministic。

至少覆盖：

1. 从 Reconstruction 进入 Reference Candidate Review。
2. 通过 UI 输入固定公开 DOI / title / author clue。
3. Query Preview 正确显示 outbound clue/provider plan。
4. 用户显式确认 lookup 后才发生网络请求。
5. 得到候选时：candidate row 可见，title/year/DOI/provider provenance/confidence/match reasons 至少核心字段可见。
6. Confirm candidate。
7. candidate 能进入 confirmed state。
8. Reject / Reopen 至少覆盖其中一个 reversible transition，再恢复 confirmed 或 pending 合理状态。
9. 编辑 Seminar Brief 至少一个字段并保存。
10. force-stop / relaunch 后 confirmed reference 与 Brief edit 仍存在。

### Network determinism

选择一个稳定的公开 metadata fixture，并在 result 中记录其 DOI/title。

对临时 provider outage / 429 / DNS / timeout：

- bounded retry；
- 记录为 `BLOCKED_BY_EXTERNAL_PROVIDER`，而不是误判 production UI regression；
- query preview、offline/error UI 与本地 persistence 仍继续验收。

禁止通过私人 API key 或付费服务来让测试变绿。

# B06 — Transcript / Summary local-safe flow

只测试当前真实 local-safe 能力，不要求未配置的真实 ASR/LLM provider magically work。

至少覆盖：

1. 从当前 seminar 进入 Transcript Review。
2. manual transcript import，通过 UI 粘贴多行 synthetic text。
3. transcript / segments 可见。
4. 编辑至少一条 segment 并保存。
5. force-stop / relaunch 后 transcript edit 仍存在。
6. 检查 transcription / summary processing status UI。
7. 未配置 live provider 时必须显示明确 unavailable / not configured 状态，不 crash、不伪造输出。
8. 如果当前 UI 已支持 local summary draft edit/apply：
   - 编辑 draft；
   - 保存；
   - 用户显式 Apply to Seminar Brief；
   - Brief 对应字段更新且不会后台覆盖其他用户内容。
9. 如果没有可由纯 UI 创建 draft 的入口且必须依赖未配置 provider，则把 generated-draft creation 标记 `EXPECTED_DEFERRED_PROVIDER_PATH`，不要新增假 provider 到 production。

# B07 — Formula / Research Export

复用 B04 的 photo asset 和 B05 的 confirmed reference；若某个前置 scenario 被 emulator limitation 阻塞，应最大化独立可测部分，不要整条 task 停止。

至少覆盖：

1. Reconstruction 中 formula region create。
2. drag-to-draft selection。
3. 显式保存 region。
4. reopen/edit crop 或 label。
5. live Formula OCR 未配置时 provider status 显示正确 unavailable state。
6. manual LaTeX 输入 / durable queue / result 可达。
7. READY/manual formula result 重开后仍存在。
8. Markdown / ZIP export surface 可达。
9. confirmed references 的 BibTeX / RIS save/share/export surface 可达。
10. Notion-ready local save/share surface 可达；不得要求 Notion OAuth。

### Export validation

优先通过 Android document picker 保存 synthetic export 到 Emulator 可检查位置，然后验证：

- 文件实际存在；
- 非零大小；
- MIME/扩展名合理；
- 对文本型 export（Markdown/BibTeX/RIS）可通过 emulator shell 读取生成文件的最小关键内容，确认不是空壳；
- ZIP 可做基本可打开/条目存在检查。

这些检查只能针对本 task synthetic seminar 生成的文件。

# Timeout / polling

继续使用第一阶段规则：

- 普通 ADB/UI 操作 hard timeout 30–60 秒；
- UI stable wait 通常 <= 15 秒；
- 每 15–30 秒有进度；
- network lookup 采用 bounded timeout/retry；
- timeout 先采 screenshot/UI tree/logcat；
- 禁止通过重启 ADB/USB/usbipd/WSL 解决 timeout。

# Automatic fixes

发现以下普通问题直接修并复测：

- controls 缺 accessibility semantics；
- 页面不可滚动 / 控件不可达；
- navigation route 错；
- processing state 卡死；
- persistence/reopen 错误；
- confirm/reject/reopen 状态错误；
- manual transcript / formula edit 保存错误；
- export 为空、文件名/MIME/内容错误；
- crash / ANR；
- test harness 稳定性问题。

不要每个 bug 都停下来问用户。

如果修 production code，补 focused regression，并在最后跑现有 unit/build/lint + Emulator regression。
