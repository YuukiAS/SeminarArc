# 0.4.x Summary Durable Queue Result

## Status

Implemented.

## Changes

- Added `SummaryDraftWorkPayload` as the bounded serializable WorkManager payload for selected summary draft input.
- Bumped Room from version `5` to version `6`; added `processing_jobs.inputPayloadJson`, `MIGRATION_5_6`, migration coverage, and schema `6.json`.
- Extended `ProcessingJob` / `ProcessingJobEntity` / `EnqueueProcessingJobInput` and duplicate-active-job lookup so payload-sensitive durable jobs do not collapse unrelated summary selections.
- Added `ProcessingWorkScheduler.enqueueSummaryDraft` and wired Transcript Review's summary action to enqueue the current transcript segments.
- Updated `ProcessingWorker` to execute `SUMMARY_DRAFT` jobs through `DraftSummaryForSeminarUseCase` and to preserve nonretryable validation/provider-unavailable failures.
- Added `UnavailableSummaryProvider` as the default local-safe provider boundary.
- Reused the worker-owned `TRANSCRIPTION` job id in `RunTranscriptionForRecordingUseCase` so durable transcription work does not create a second processing job when executed.

## Privacy / Scope Boundary

- Tapping the summary action creates local durable work only.
- The default provider remains `UnavailableSummaryProvider`, so transcript text, references, notes, recordings, photos, OCR corpus, exports, logs, and app-private paths are not uploaded.
- No live LLM summary provider, provider picker, Notion OAuth/upload, backend, private credential, or recurring-cost service was added.
