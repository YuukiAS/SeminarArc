# 0.5.x Exploratory Stress And Emulator Matrix

## 目标

在已通过的 deterministic black-box、第二轮真实素材和 visual regression 基础上，完成 bounded fixed-seed exploratory stress，并建立 API 36 phone、小屏 profile 与一个仍在 `minSdk = 26` 支持范围内的旧 API Emulator 关键流程矩阵。发现普通 crash、ANR、lifecycle、persistence、layout、cleanup 或 harness 问题时直接修复、补回归并重跑。

## 当前用户授权对应关系

本 task 来自当前总 Goal 的明确要求：visual regression 稳定后立即建立并执行 `0.5.x_exploratory_stress_task`，允许 Emulator 重启和普通测试问题自恢复，不需要再次等待用户确认。

## 允许动作

- 在 `emulator-5554` 上运行 package-scoped、fixed-seed、bounded Monkey。
- 对明确的 `emulator-*` serial 执行 install、`pm clear`、force-stop、launch、logcat、UI tree、screenshot、instrumentation 和 app-owned synthetic cleanup。
- 显式设置并恢复 API 36 Emulator 的 small-screen display profile。
- 如果本机缺少旧 API 环境，从 Google 官方 Android SDK repository 下载 Windows command-line tools 和 `system-images;android-29;google_apis;x86_64`。
- 在 D: 项目本地 ignored Android home/AVD 目录创建 `SeminarArc_API29`，以独立端口和 hidden/headless 模式启动、停止和重建该 task-owned synthetic AVD。
- 修改 bounded stress harness、普通 production bug、测试和文档；写 result/review 并创建普通 commit。

## 禁止动作

- 不触碰 GM1910 / `8cc54656`，不对它执行 shell、install、input、instrumentation、scrcpy、transport 或恢复操作。
- 不运行任何 unscoped `connected*AndroidTest` / `device*AndroidTest`。
- 不执行 `adb kill-server`、transport reset、usbipd、`wsl --shutdown` 或 physical reboot。
- 不使用 Firebase Test Lab，不创建 Firebase/云/付费资源。
- 不上传真实 seminar 照片、录音、OCR、transcript 或 private evidence。
- 不删除或改写用户现有 `Pixel_8` AVD；task-owned API 29 AVD 必须与它隔离。
- 不创建 tag、Release、production signing、Google Play 或公开发布。

## Bounded Monkey 合同

- package：`com.yuukias.seminararc.internal`
- 固定 seed：至少 3 个，记录到 result；失败必须可用同一 seed 重放。
- 每个 seed 事件上限：不超过 1,000；总事件上限：不超过 4,000。
- 禁用 system key、app switch 和 unrestricted any-event 百分比。
- 每轮前使用 fresh synthetic app state；每轮后 force-stop/relaunch 验证恢复，再清理 app-owned synthetic data。
- 记录 Monkey stdout、crash buffer、package-filtered ANR/crash evidence、恢复 UI tree 和耗时到 ignored private evidence。
- crash/ANR 出现后先用同一 seed 重放；确认可复现则修复并增加 regression，不通过 `--ignore-crashes` / `--ignore-timeouts` 把失败改成 PASS。

1. 所有设备写操作都带显式 `-s emulator-*`；inventory 同时出现 physical serial 时仍不得目标化。

3. 每个 seed 没有未解释的 crash/ANR，且 force-stop 后能重新进入 App。
4. small-screen profile 在 `finally` 中恢复原显示配置。
5. API 29 与 API 36 的关键路径结果分开记录，不把一个 API 的 PASS 外推到另一 API。
6. 所有 private logs/screenshots/UI trees 保持 ignored；tracked result 只含聚合结论和匿名 run id。
7. `git diff --check`、相关 Gradle/JVM/lint/Emulator regression 通过。
