# 0.5.x Black-box Acceptance Harness Task

## Goal

建立 SeminarArc 第一版可重复运行的 Windows Emulator 黑盒验收 harness，优先自动覆盖基础真实用户路径，减少用户逐页逐按钮手工验收。

本 task 只做 harness foundation + 基础 scenario：

- B01 Fresh install / empty library
- B02 Seminar CRUD / persistence
- B03 Session lifecycle 的 Emulator-safe 部分
- B08 Recovery / cleanup

详细长期范围见：

`docs/plans/0.5.x-blackbox-acceptance-plan.md`

本 task 不做科研工作流 B04-B07、不做 screenshot golden、多设备矩阵、Firebase Test Lab，也不开发新的产品能力。

## Environment

Windows native checkout：

`D:\Code\SeminarArc-emulator`

SDK：

`D:\Android\Sdk`

默认目标：Windows Emulator。

必须现场运行：

```powershell
D:\Android\Sdk\platform-tools\adb.exe devices -l
```

如果 inventory 同时看到 protected physical serial，允许继续，但所有非 inventory ADB 命令必须显式：

`-s <实际 emulator serial>`

严禁对 GM1910 / `8cc54656` 运行 shell、install、input、instrumentation、scrcpy 或 transport 操作。

## Black-box contract

验收执行阶段把安装后的 internal APK 当成黑盒。

允许：

- accessibility/UI Automator tree；
- `adb shell input`；
- screenshot；
- package manager / ActivityManager；
- scoped logcat；
- Android 系统 dialog/picker。

禁止通过以下方式伪造用户成功：

- 直接写 Room；
- repository/use-case injection；
- test-only navigation shortcut；
- 静态假页面或内存假状态。

Test setup 可以在 Emulator 上清理 `com.yuukias.seminararc.internal` app data，因为 Emulator 是 disposable test target。

## Deliverable A — Harness

创建长期入口：

`scripts/run-blackbox-acceptance.ps1`

并按需要创建：

`scripts/blackbox/`

至少具备：

1. 自动发现/验证目标 emulator serial；
2. explicit serial guard；
3. launch / force-stop / clear-data helpers；
4. UI tree dump；
5. 从 UI tree 查找 node 并计算点击位置，禁止仅凭 screenshot 猜坐标；
6. tap / text / swipe / back；
7. screenshot capture；
8. scoped crash/error logcat；
9. timeout/retry；
10. scenario PASS/FAIL summary。

优先使用现有 Windows PowerShell + Android SDK/ADB；不要为了第一版强制安装 Appium/Maestro 等额外框架。

## Evidence

默认写到：

`private/blackbox-acceptance/<run-id>/`

每个 scenario 至少生成：

- summary JSON/Markdown；
- final screenshot；
- failure screenshot（如有）；
- relevant UI tree；
- scoped logcat on failure；
- elapsed time；
- version/package/emulator serial。

`private/` 大体积运行证据不得提交 Git。

可以提交：

- harness code；
- compact testcase definition；
- 小型 deterministic fixture；
- task/result/docs。

## B01 Fresh install / empty library

从 clean internal package state：

1. launch `com.yuukias.seminararc.internal`；
2. 确认 app process 正常；
3. 确认 library empty state 可见；
4. 确认 Create/New seminar entry 可达；
5. capture screenshot / UI tree；
6. crash buffer 无 app crash。

## B02 Seminar CRUD / persistence

完全通过用户可见 UI：

1. 打开 New seminar；
2. 验证空 title 不能正常保存为有效 seminar；
3. 创建 synthetic seminar，例如：
   - title: `Blackbox Acceptance Seminar`
   - speaker: `Test Speaker`
   - affiliation: `SeminarArc QA`
   - location: `Emulator Room`
   - abstract: 一段足够长的测试文本；
4. 保存；
5. library 能找到该 seminar；
6. reopen；
7. 修改至少一个字段；
8. 返回 library；
9. force-stop app；
10. relaunch；
11. 数据仍存在且修改值正确。

如果 date/time picker 可以稳定自动驱动，则覆盖；否则记录为 `NOT_COVERED_IN_FOUNDATION`，不要为此阻塞 task。

## B03 Session lifecycle — Emulator-safe portion

基于 synthetic seminar：

1. 进入 detail；
2. Start seminar；
3. 验证 permission denied / permission prompt / granted 状态中当前 Emulator 可安全覆盖的部分；
4. Active Session UI 可达；
5. 添加 NOTE；
6. 添加 QUESTION；
7. 添加 MARK（若当前 UI/recording precondition 允许）；
8. End Seminar；
9. 回到 completed/detail flow；
10. force-stop / relaunch 后 completed 状态仍在。

本 task 不把以下内容作为 PASS 必需条件：

- 真实麦克风音质；
- 真实 CameraX 拍投影质量；
- 厂商 ROM 锁屏后台行为。

如果 Emulator 某硬件限制阻止一步，必须标记：

`BLOCKED_BY_EMULATOR_LIMITATION`

而不是要求用户立即手工测试。

## B08 Recovery / cleanup

1. 在 synthetic seminar 已存在的状态 force-stop / relaunch；
2. 确认关键状态仍存在；
3. 通过 UI 删除 synthetic seminar；
4. 回到 library 后不再显示该 seminar；
5. force-stop / relaunch；
6. seminar 仍不存在；
7. app 无 crash。

只删除本 task 创建的 synthetic seminar。

## Timeout policy

必须避免长时间静默挂起：

- 普通 ADB / UI 操作 hard timeout：30–60 秒；
- UI stable wait：通常 <= 15 秒；
- 每 15–30 秒产生一次进度；
- timeout 时先 capture screenshot + UI tree + logcat；
- 可以针对 Emulator-side transient failure 做有限 retry；
- 禁止通过 `adb kill-server`、USB reset、usbipd、WSL shutdown 解决 timeout。

## Automatic fixes

如果发现普通：

- accessibility semantics 缺失；
- 控件不可通过 UI tree 定位；
- navigation bug；
- persistence bug；
- layout clipping/scrolling bug；
- delete flow bug；
- process restart bug；

允许直接修复 production/test code，并补 regression。

不要因为普通 bug 停下来询问用户。

但不要为了自动化测试增加用户不可见的 backdoor/test-only production behavior。

## Validation

完成后至少运行：

- 当前必要 JVM/build/lint gate；
- harness B01/B02/B03/B08；
- 若生产代码被修改，运行当前仓库批准的 Emulator instrumentation regression。

普通文档/测试提交不要创建 version tag，也不要触发版本 GitHub Actions。
