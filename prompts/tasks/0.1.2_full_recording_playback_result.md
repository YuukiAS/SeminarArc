## Playback architecture

- `RecordingPlaybackController` 暴露 sealed controller state：`Idle`、`Preparing`、`Ready`、`Playing`、`Ended`、`Error`。
- `Media3RecordingPlaybackController` 使用 Media3 `ExoPlayer`，内部管理 `Player.Listener`、500ms position tick、prepare/play/pause/seek/release。
- Controller 绑定到 Hilt `ViewModelComponent`，避免 app-wide singleton player。
- Compose 只消费 `RecordingPlaybackUiState` 并发送用户动作，不直接管理 ExoPlayer callback。
- ViewModel 不持有 Android View，只持有 controller abstraction 和已解析的当前 playable `File`。

## Media3 lifecycle

- Detail 页面进入后可按需 `prepare` 并播放。
- 页面离开时 `DisposableEffect.onDispose` 调用 `onPlaybackSurfaceDisposed()`，释放 controller。
- `ViewModel.onCleared()` 再次调用 release，确保 Activity recreation、返回栈清理和 seminar 删除路径不会让 player 继续播放。
- `prepare`、`play`、`pause`、`seekTo`、`release` 均设计为重复调用安全。
- 本阶段没有 `MediaSessionService`、lock-screen/media notification controls 或 background playback。

## Playable 判定

播放入口只在以下条件同时满足时可用：

- seminar 存在并可显示 Detail；
- recording row 属于当前 `seminarId`；
- `RecordingState == COMPLETED`；
- `filePath` 非空且通过 storage boundary 解析；
- app-private 文件实际存在、是普通文件并可读。

## File resolution

- Room 继续保存相对路径，例如 `seminars/12/recordings/recording.m4a`。
- 新增 `MediaStorageManager.resolveReadableRelativeFile(relativePath)`。
- `AppMediaStorageManager` 使用 `context.filesDir.canonicalFile` 校验路径，不接受空路径、绝对路径或越界路径。
- UI 层不拼接 `context.filesDir + filePath`。

## Multiple recording selection

- 新增 `RecordingRepository.observeRecordingsForSeminar(seminarId)` 和 DAO 查询，按 `startedAt DESC, id DESC` 返回同一 seminar 的全部 recording rows。
- Detail playback 选择规则：
  - 若存在 `RECORDING` row，显示 recording in progress，不提供 completed playback，由 Active Session 负责现场状态。
  - 否则选择最新可读的 `COMPLETED` recording。
  - 最新 `FAILED` row 不会遮蔽旧的合法 completed recording。
  - 如果存在 completed rows 但都没有可读文件，显示 `MissingFile`。
  - 不做多段 merge、stitching 或 clip generation。

## Missing / failed handling

- `FAILED` recording 显示“Recording did not finish normally”，不当作可靠 full recording 播放。
- `COMPLETED` 但文件缺失显示 `Recording file is missing.`。
- Playback error 映射到 `RecordingPlaybackUiState.PlaybackError`；Seminar Detail 的标题、abstract、timeline preview、delete 等其他内容仍可浏览。
- 缺失文件不会导致 crash，不会删除 seminar，不会静默修改 Room row。

## 测试覆盖

新增 JVM tests 覆盖：

- `COMPLETED + file exists -> Ready`
- `COMPLETED + file missing -> MissingFile`
- `FAILED -> FailedRecording`，不提供 player
- `RECORDING -> RecordingInProgress`，不提供 completed playback
- no recording -> `NoRecording`
- latest `FAILED` 不遮蔽旧 completed recording
- play / pause state transition
- seek position update
- playback error -> `PlaybackError`
- release idempotent
- playback error 时 Detail 其他内容仍存在
