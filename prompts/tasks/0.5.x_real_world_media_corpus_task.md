# 0.5.x Real-world Media Corpus Task

## Goal

在 deterministic black-box B04/B07 已通过 imported-photo path 的基础上，用用户本机私有的真实 seminar 照片/PDF 做 robustness 验收，验证真实投影环境下的图像导入、增强、OCR、key-slide、formula-region 与 PDF 生命周期，而不是再次验证基础 navigation 是否存在。

本 task 不把真实素材提交 Git，不上传任何第三方 provider，也不接 OpenAI / Mathpix / ASR / LLM / Notion OAuth。

## Precondition / private fixture location

Windows checkout：

`D:\Code\SeminarArc-emulator`

用户私有 fixture 根目录固定为：

`private\blackbox-fixtures\real-world\`

该路径位于现有 `.gitignore` 已忽略的 `private/blackbox-fixtures/` 下。

建议结构：

```text
private/blackbox-fixtures/real-world/
  photos/
  pdfs/
```

用户无需重命名或手工写 manifest。Codex 自动扫描、hash、分配匿名 sample id（如 `RW-P001` / `RW-D001`），本地生成 ignored manifest。

开始前检查：

- 至少 5 张可读图片（jpg/jpeg/png/webp/heic/heif）；
- PDF 0–2 份均可，PDF 缺失不阻塞 photo corpus；
- 如果图片不足 5 张，停止为 `NEEDS_PRIVATE_FIXTURES`，不要继续改代码。

## Privacy contract

真实 seminar fixtures 默认可能包含版权、未公开研究或其他敏感内容。

严格禁止：

- `git add` / commit / push fixture 文件；
- 把真实图片/PDF放入 tracked docs/assets/test resources；
- 上传 GitHub Release / Actions artifact；
- 调用任何云 OCR / LLM / Mathpix / reference provider 发送真实图片、PDF、OCR 全文或抽取文本；
- 在 tracked result 中复制完整 OCR 文本、讲者敏感信息、图片截图或 PDF 内容。

允许写入 Git 的只有：

- harness / production bug fix；
- 匿名 sample id；
- 聚合统计；
- 不泄露原文的 failure category；
- task/result/review 文档。

运行截图、OCR 全文、manifest、hash、文件名映射等证据全部保留在 ignored private evidence 目录。

## Corpus inventory

创建/扩展一个可重复入口，例如：

`scripts/run-real-world-media-corpus.ps1`

自动：

1. 扫描 photos/pdfs；
2. 为每个文件计算 SHA-256；
3. 分配匿名 sample id；
4. 记录文件类型、大小、图片尺寸（若可安全读取）；
5. 生成 local-only manifest；
6. 不要求用户手动分类。

如果 Codex 能通过本地视觉检查安全判断样本类别，可在 private manifest 中标记：title/overview、dense text、reference-heavy、formula-heavy、figure/chart、hard/skew/glare/blur；无法判断时保留 `unknown`，不要猜。

## Photo robustness flow

对 5–10 张有代表性的真实图片执行，优先避免重复近似照片。

每张图片通过真实用户路径进入 App：

Windows private fixture -> push/copy 到 Emulator user-visible storage -> Android system picker -> `Import slide image` -> app-private `PHOTO_ORIGINAL`。

禁止直接写 Room。

至少验证：

- import 成功且 preview 可见；
- force-stop / relaunch 后仍存在；
- image enhancement 至少跑默认路径；
- local ML Kit OCR job terminal state；
- OCR 有输出时可打开/edit/save；
- key-slide toggle 可持久化；
- formula-heavy/代表性图片至少一张可进入 formula region drag/save/edit + manual LaTeX；
- 全流程无 crash/ANR。

### Robustness metrics

本阶段不是精确 OCR benchmark，但要记录每个匿名样本：

- import PASS/FAIL；
- enhancement PASS/FAIL + latency；
- OCR terminal state + latency；
- OCR output 是否为空；
- OCR 输出字符数/行数等非内容统计；
- 是否能看到可用的 title/DOI/reference clue（只记录 boolean/category，不把真实 clue 写进 tracked result）；
- formula-region UI 是否可用；
- crash / timeout / processing failure category。

如果 enhancement 后 OCR 明显比原图更差，可记录 `POSSIBLE_ENHANCEMENT_REGRESSION` 并保留 private evidence，由 Codex分析是否属于 production bug。

## PDF robustness flow

如果用户提供 PDF，最多取 1–2 份做当前已有 abstract PDF 用户路径：

- system picker import；
- app 内关联 seminar；
- force-stop/relaunch persistence；
- replace/remove 生命周期（可在 synthetic seminar 上操作副本）；
- 不上传、不做云解析。

如果当前产品并不对 PDF 做页面 OCR/公式识别，不要扩展 scope 去实现。

## Automatic fixes

发现以下真实 production 问题可直接修并复测：

- legitimate image format 无法 import；
- import 后 preview/persistence 丢失；
- 大图导致明显 OOM/crash；
- local enhancement/OCR worker 对真实尺寸图片异常；
- HEIC/WEBP 等已声明支持格式行为与 UI 不一致；
- formula region 在真实 aspect ratio 下不可操作；
- abstract PDF replace/remove 生命周期 bug；
- accessibility/navigation/scrolling 导致流程不可达。

不要因为单张难图 OCR 不准就重写 OCR 算法；先区分 quality limitation 与 product bug。

## Device safety

只允许 Windows Emulator。

如果 ADB inventory 同时看到 physical serial，沿用 mixed-inventory explicit-emulator lane；所有非 inventory ADB 命令显式 `-s <emulator>`。

禁止操作 GM1910 / `8cc54656`，禁止 `adb kill-server`、usbipd、WSL shutdown、physical install/input/instrumentation。

## Runtime / timeout

这轮必须比早期全 catalog 更受控：

- 默认选择最多 10 张图片 + 2 PDF；
- 单图片 OCR/enhancement 使用 bounded wait；
- 每 15–30 秒输出进度；
- 单样本反复失败最多有限 retry；
- 某个坏样本不得阻塞其余 corpus；
- 目标总 runtime 约 1–3 小时，不允许无限调参。

## Validation

完成后：

1. 写 private corpus summary/evidence；
2. 如果 production code 有改动，跑 focused unit test + `testDebugUnitTest assembleInternal lintDebug`；
3. production code 有改动时跑批准的 Emulator instrumentation regression；
4. 至少重跑 imported-photo B04/B07 deterministic focused regression，确保真实 corpus 修复没有破坏 deterministic path；
5. `git diff --check`；
6. 创建 tracked result；
7. commit + push main。

不要创建 tag / Release。
