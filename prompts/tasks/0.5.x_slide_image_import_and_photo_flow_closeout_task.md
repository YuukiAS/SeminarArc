# 0.5.x Slide Image Import + Photo Flow Closeout Task

## Goal

不要继续死磕 Windows Emulator camera fixture。

新增一个对真实用户有价值、同时可 deterministic black-box 测试的 **Import slide image** 路径：用户从 Android 系统 picker 选择已有 seminar slide/photo，SeminarArc 将其复制到 app-private storage，并登记为 seminar-scoped `PHOTO_ORIGINAL` asset。

随后使用现有 deterministic synthetic PNG 通过系统 picker 导入，关闭：

- B04 Reconstruction
- B07 Formula / Research Export 的 photo-dependent path

CameraX capture 本身继续保留为独立真实硬件 acceptance，不因为本 task 通过就宣称 CameraX black-box fixture 已解决。

## Product semantics

这是正式用户能力，不是 test-only backdoor。

用户真实场景包括：

- seminar 时已经用系统相机拍过 slide；
- seminar 后拿到截图/图片；
- 需要补充遗漏的 slide；
- CameraX 现场采集失败后仍希望把已有图片导入 SeminarArc 整理。

Import slide image 必须 local-first，不上传网络。

### Timeline semantics

Imported image **不得伪造现场时间点**。

保存为：

- `SeminarAssetType.PHOTO_ORIGINAL`
- 当前 seminar ownership
- `sourceTimelineEventId = null`
- `sourceRecordingId = null`
- `sourceClipId = null`

不要创建假 `PHOTO` timeline event，不要制造假 recording offset。

如果 UI 需要区分 captured/imported，可用现有 nullable source association 或轻量 display metadata；优先避免 Room schema migration，除非实现审查证明确有必要。

## User-facing entry

优先把入口放在 Reconstruction workspace，因为导入后的用途就是 OCR / enhancement / key slide / formula / research。

建议清晰文案，例如：

- `Import slide image`

使用 Android 官方 system picker / Activity Result contract，只接受合理 image MIME。

要求：

- cancel 安全；
- unsupported/broken URI 有可读错误；
- 不长期依赖外部 URI permission；
- 应把内容复制到 app-owned seminar media storage；
- 导入后立刻作为 Reconstruction photo item 可见；
- 原始图片不被 enhancement 覆盖。

## Data / repository work

建立清晰 domain/repository/use-case 路径，不让 composable 直接写 Room。

如当前 `ReconstructionRepository` 只能创建 derived asset，可增加明确的 original imported photo API/input，例如等价于：

- `ImportPhotoAssetInput`
- `importOriginalPhoto(...)`

命名遵循现有代码风格。

必须验证：

- seminar ownership；
- unique relative path；
- MIME / display name；
- app-private file copy 成功后才创建 durable asset；
- DB insert 失败时不要留下明显 orphan 文件；
- file copy 失败时不要留下 asset row；
- seminar 删除时继续沿现有 app-owned cleanup contract 清理。

不要为了 import 增加 cloud storage / MediaStore 写回 / account 权限。

## Deterministic fixture path

复用：

`scripts/blackbox/New-DeterministicCameraFixture.ps1`

生成：

`private/blackbox-fixtures/seminararc-camera-fixture.png`

本 task 可以把 fixture 复制/推送到 Emulator 的用户可见位置，例如 `/sdcard/Download/`，然后通过 Android system picker 完成真实用户可见 import。

允许 test harness 驱动系统 picker，但禁止：

- 直接写 Room；
- 直接调用 repository 来绕过 UI；
- test-only production shortcut；
- 隐藏 backdoor。

## B04 completion gate

通过 imported deterministic fixture，必须 black-box 覆盖：

1. Reconstruction 打开 system picker；
2. 选中 synthetic fixture；
3. imported photo item 出现；
4. photo preview 可见；
5. enhancement action 可完成并产生合理 result/state；
6. OCR action 可完成；
7. deterministic fixture 至少能识别一个稳定 clue（优先 DOI `10.1038/nature12373` 或固定英文标题片段）；
8. OCR edit 保存；
9. key slide toggle 保存；
10. force-stop / relaunch 后 imported photo / OCR edit / key-slide 状态仍存在。

如果 exact 中文 OCR 有模型波动，不把中文 exact match 作为唯一 PASS 条件；但 OCR pipeline 必须真实跑完。

## B07 completion gate

复用同一 imported photo asset，必须 black-box 覆盖：

1. formula region drag-to-draft；
2. save region；
3. reopen/edit label/crop；
4. live Formula OCR unavailable 状态正确；
5. manual LaTeX path 可完成；
6. READY/manual result 持久化；
7. force-stop / relaunch 后仍存在；
8. Markdown / ZIP export 至少包含 formula-related内容或当前 renderer 预期表示；
9. 若 B05 confirmed reference fixture 可独立复用，不要求本 task 网络 lookup；不要因为 provider outage 阻塞 B07。
