# 0.1.x Windows Emulator Onboarding And Regression Task

## 目标

把 SeminarArc 后续 Android 自动化测试主链路正式迁移到 Windows Emulator，并验证现有 `0.1.5` 在 Emulator 上的 build/instrumentation/regression 基础。

当前用户已经在 Windows 安装 Android Studio，Windows SDK 路径为：

`D:\Android\Sdk`

用户已经创建并点击启动一个 Android Emulator。实际 AVD 名称、API、serial 由本 task 现场确认，不要猜。

本 task 同时只对 protected physical GM1910 做**一次开始前只读在线检查 + 一次 Emulator 配置完成后的只读 postflight**；除此之外禁止操作真机。

原 `0.1.x_local_mvp_device_acceptance_resume_task.md` 已 supersede。不要恢复完整真机 E2E，不要把物理验收缺口重新变成当前 blocker。

`/home/yuukias/code/SeminarArc`

`git pull --ff-only origin main`

然后完整读取：

- `AGENTS.md`，特别是 `Emulator-first 测试策略` 和 `真机解锁与设备操作安全`

## 一、Physical device 只读 preflight

只运行：

`/home/yuukias/Android/Sdk/platform-tools/adb devices -l`

目标只是确认 protected physical device 当前是否仍以 `device` 在线。

如果看到历史 serial `8cc54656`：记录 `PHYSICAL_DEVICE_ONLINE`。

如果没看到或状态异常：记录 `PHYSICAL_DEVICE_CHANNEL_UNAVAILABLE`，**不要尝试任何恢复，也不要因此阻塞 Emulator task**。

本阶段禁止对 physical serial 执行任何其他 ADB shell/install/input/scrcpy 操作。

## 二、检查 Windows Emulator 基础设施

通过 WSL 调用 Windows PowerShell 或 Windows executable，只操作 Windows Android SDK / Emulator。

检查：

- `D:\Android\Sdk\platform-tools\adb.exe` 存在
- `D:\Android\Sdk\emulator\emulator.exe` 存在
- `D:\Android\Sdk\emulator\emulator.exe -accel-check`
- `D:\Android\Sdk\emulator\emulator.exe -list-avds`
- Windows ADB：`D:\Android\Sdk\platform-tools\adb.exe devices -l`

要求：

1. 至少一个目标 `emulator-*` 状态为 `device`。
2. Windows ADB **不得看到** physical serial `8cc54656` / GM1910。
3. 如果 Windows ADB 看见 physical device，停止 Windows connected/instrumentation 子流程，记录 `ADB_TRANSPORT_ISOLATION_FAILED`，但继续 WSL headless 检查和文档；不得调整 usbipd 或 ADB transport。
4. 如果 Emulator 尚未真正启动，但存在明确的 AVD，可以只启动 Windows Emulator；这是允许的。不得为此修改 WSL networking、运行 `wsl --shutdown` 或碰 usbipd。

记录实际：

- AVD name
- emulator serial
- API level
- ABI/system image
- device profile（如可安全读取）

## 三、建立 Windows Emulator test mirror

canonical repo 始终是：

`/home/yuukias/code/SeminarArc`

Windows/NTFS 测试镜像建议：

`D:\Code\SeminarArc-emulator`

对应 WSL 路径：

`/mnt/d/Code/SeminarArc-emulator`

规则：

- 如果 mirror 不存在，clone `YuukiAS/SeminarArc` 当前 `main`。
- 如果存在且 clean，`git fetch` + `git pull --ff-only`。
- 如果存在但有未提交修改，不得删除/覆盖；创建一个新的唯一 testing mirror 或记录并使用其他 clean path。
- mirror 仅跑 Windows build/test，不在其中形成独立产品开发历史。
- 确认 mirror HEAD 与 canonical `origin/main` 相同。

在 Windows mirror 创建本地 `local.properties` 指向：

`D:\Android\Sdk`

该文件不得提交。

## 四、Windows Java / Gradle 环境

优先复用 Android Studio 自带 JBR；不要额外安装系统 JDK，除非确实必要并先说明。

安全检查：

- Windows `java -version` 是否可用；
- 如不可用，检查 Android Studio 常见 `jbr` 路径并使用其 `java.exe`；
- 不修改全局系统 PATH，优先对单次 PowerShell/Gradle invocation 设置 `JAVA_HOME`。

允许 Windows Gradle cache 与 WSL 重复。隔离比节省下载空间更重要。

## 五、Windows mirror headless build

在 Windows mirror 使用 `gradlew.bat` 运行：

- `testDebugUnitTest`
- `assembleDebug`
- `lintDebug`

允许联网下载 Windows 环境缺失的 Gradle/Maven dependencies。

如果出现正常代码或依赖问题，定位并修复；如果修复属于产品代码，应回到 canonical WSL repo 修改、验证、commit + push，再同步 Windows mirror。不要把 mirror 中未同步修改作为最终实现。

## 六、Emulator connected/instrumentation regression

只有当 Windows `adb.exe devices -l` 明确满足：

- 目标列表中只有预期 Emulator device(s)；
- 没有 `8cc54656` / GM1910 / 其他 physical serial；
- 目标 Emulator 为 `device`；

才允许运行 connected/instrumentation。

优先运行当前仓库已有 Android instrumentation / Room migration / Compose tests，包括：

`gradlew.bat connectedDebugAndroidTest`

如果 Windows ADB 同时有多个 emulator 导致 connected task 目标不明确，不要为了方便碰 physical transport；可以选择安全的 emulator-specific 执行方式，或记录多 Emulator 配置问题并继续其他 Emulator regression。

connected test 失败如果是 app/test bug：修复并重跑。

禁止为了让测试变绿而删除 migration/instrumentation tests 或降低 invariant。

## 七、Emulator smoke

在 Emulator 上至少做：

- app 安装/启动
- Seminar list/detail 基本导航
- Room migration 启动不 crash
- Active Session UI 基础进入路径
- timeline/review 页面能打开
- export UI surface 可进入

CameraX、麦克风等可在 Emulator 做流程级 smoke，但**不要把 Emulator 成功写成真实硬件 acceptance**。

不要求本 task 重新完成旧的 full physical E2E。

## 八、Physical device 只读 postflight

Windows Emulator / connected regression 完成后，再且只再运行一次：

`/home/yuukias/Android/Sdk/platform-tools/adb devices -l`

如果 GM1910 仍为同一 serial / `device`：记录 `PHYSICAL_TRANSPORT_UNCHANGED`。

如果消失：记录 `PHYSICAL_DEVICE_CHANNEL_CHANGED_DURING_EMULATOR_SETUP`，禁止恢复；但 Emulator/headless 已完成的结果仍然保留，不把整个开发线回滚或重新 stall。

此后本 task 不再操作 physical device。

## 十、状态语义

不要把 physical-device 不可用自动写成整个 task `blocked`。
