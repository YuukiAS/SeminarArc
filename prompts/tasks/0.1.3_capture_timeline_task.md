# 0.1.3 Capture Timeline Task

## 目标

按 `docs/plans/0.1.3-capture-timeline-plan.md` 完整实现 `0.1.3` Capture + Timeline 阶段：现场 record/photo 或 photos-only 采集、CameraX 照片、`MARK` / `PHOTO` / `QUESTION` / `NOTE` 事件、统一 timeline 和 `Play from here`。

## 范围

- 复用现有单模块 Android/Compose/Room 架构。
- 复用已有 `TimelineEventEntity` schema，除非发现不可避免的 Room migration 需求。
- 实现 app-private `files/seminars/<seminarId>/photos/` photo storage。
- 实现 live capture offset 计算：录音模式基于 recording start，photos-only 基于 seminar session start。
- 实现 photo-only seminar session，不依赖 microphone permission。
- 实现 CameraX preview/capture，保存后立即创建 `PHOTO` event，并提供 last-photo feedback / undo / retake。
- 实现 `MARK` / `QUESTION` / `NOTE` write path 和 UI。
- 实现统一 timeline review route，按 offset 混排所有 event，支持 photo preview/missing-file state、删除 photo event 清理 owned file、recording 存在时 `Play from here`。

## 禁止事项

- 不实现 OCR、formula OCR、transcription、AI summary、paper lookup、DOI、Notion、cloud sync、login、ads、payment、analytics。
- 不伪造 CameraX、timeline event、clip 或 playback 完成。
- 不提交 APK、录音、照片、导出 ZIP、私人媒体、build artifacts、本地配置或凭据。
- 不断开真机、不重启真机、不删除或移动真机用户内容。

## 验证要求

- `./gradlew testDebugUnitTest`
- `./gradlew assembleDebug`
- `./gradlew lintDebug`
- `git diff --check`
- 有设备时执行非破坏 CameraX smoke test：Record + Photos、Photos only、mark/note/question/photo、timeline ordering、Play from here、删除 photo event 清理 app-owned file。

## 完成条件

- `0.1.3` gate 通过或记录明确 hard blocker。
- 写入 `prompts/tasks/0.1.3_capture_timeline_result.md`。
- commit + push `main` 后继续 `0.1.4`。
