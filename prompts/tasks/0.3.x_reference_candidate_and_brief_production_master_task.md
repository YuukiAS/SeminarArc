# Phase 1：Room v4 / Domain Foundation / Fake Providers

先创建内部 task/result，例如：

- `0.3.x_reference_schema_domain_task.md`
- `0.3.x_reference_lookup_provider_boundary_task.md`

## 1.1 v4 schema

从当前真实 Room v3 显式升级到 v4。

必须新增最小必要表：

- `ReferenceEvidenceEntity`
- `ReferenceLookupAttemptEntity`
- `ReferenceCandidateEntity`
- `ReferenceCandidateSourceEntity`
- `SeminarBriefEntity`
- `BriefReferenceEntity`
- `BriefKeySlideEntity`

### Candidate canonical/source split

`ReferenceCandidateEntity` 是 app-owned canonical candidate，不绑定单一 provider。

`ReferenceCandidateSourceEntity` 记录 provider observation：

- candidateId
- provider
- providerWorkId
- DOI/title/authors/year/venue/source/type 等 normalized observation
- provider-native relevance（如果 provider 返回，仅作 provenance，不跨 provider 直接比较）
- minimal provider payload subset / metadata version
- fetchedAt

一个 canonical candidate 可以有多个 Crossref/OpenAlex/DataCite source rows。

不要默认保存完整 provider raw response，不缓存 Crossref abstract。

### Matcher version

Candidate 至少保存：

- `matcherVersion`，第一版例如 `reference-match-v1`
- `matchScore`
- `confidenceBand`
- `matchReasons` / component breakdown

使未来权重改变后旧 candidate 仍可解释。

### Migration

实现 `MIGRATION_3_4`：

- 不修改/删除 v3 assets/jobs/OCR/tags；
- 不 destructive；
- Brief lazy-create，不在 migration 中为所有 seminar 创建空 row；
- foreign key/cascade 语义明确；
- migration tests 覆盖 v3->v4 和旧版本 reopen 到 current。

Windows Emulator 最终必须真实 execute migration instrumentation。

## 1.2 Provider contracts

定义 provider-independent domain boundary，例如：

- `ReferenceLookupProvider`
- `ReferenceLookupQuery`
- `ReferenceProviderResult`
- provider error / rate-limit / offline semantics

先用 fake provider tests 完成 orchestration contract，再写 live HTTP provider。

# Phase 2：Evidence Extraction + Ranking + Dedup

建议内部 task：

- `0.3.x_reference_evidence_extraction_task.md`
- `0.3.x_candidate_ranking_dedup_task.md`

全部做成 pure Kotlin 可测试逻辑。

## 2.1 DOI

区分：

### Safe normalization

仅清理：

- `doi:` / DOI URL prefix
- surrounding brackets
- trailing punctuation
- case
- obvious line wrap/whitespace around slash

这种结果可以进入 exact DOI lookup。

### Speculative OCR repair

`O/0`、`I/l/1` 等字符替换必须生成 repair variants，保留原始 evidence 和 repair reason。

修复 variant 命中 provider DOI 后，不能因为“返回了 DOI”就自动 100/high。

只有 provider metadata 与 selected title/author/year evidence 足够一致时才能提升 confidence。

不得静默把 repaired DOI 写成用户原始 DOI。

## 2.2 Bibliographic clue extraction

实现 deterministic title/author/year/venue clue extraction。

低质量 OCR / 多 title conflict 时必须要求用户 review，不自动发 noisy request。

## 2.3 Matcher

实现 `reference-match-v1`：

- DOI evidence
- title similarity
- author overlap
- year proximity
- venue/source
- provider cross-confirmation
- evidence quality
- query type

100 分只是排序 heuristic，不是概率。

UI 只暴露 band + match reasons。

为 noisy OCR、同名论文、年份冲突、同 DOI 多 provider、无 DOI 相似标题等写 golden fixtures。

## 2.4 Dedup

- normalized DOI 优先；
- 无 DOI 时 normalized title + year + first-author overlap；
- merge provider observations 到同一 canonical candidate；
- user-confirmed/rejected 状态不得被 provider refresh 静默覆盖。

# Phase 3：Network Providers

建议内部 task：

- `0.3.x_reference_network_providers_task.md`

实现顺序：

1. Crossref primary
2. OpenAlex secondary/cross-confirmation
3. DataCite targeted fallback

Semantic Scholar 不实现。

## 3.1 Crossref

支持：

- exact DOI single record
- bibliographic list/query

必须 endpoint-aware rate limit：

- single DOI 与 list/query 分开节流；
- list query 比 single DOI 更保守；
- 优先读取 response rate-limit headers；
- 429 honor Retry-After/backoff；
- 不并发轰炸 provider。

Crossref contact/polite identity 不得凭空发明用户邮箱。

若没有已配置公开 support/contact address：

- public pool 可用；
- provider contract 允许后续配置公开 app contact 后进入 polite pool；
- 不硬编码私人邮箱或 secret。

## 3.2 OpenAlex

第一版 Android client：

- keyless fallback/cross-confirmation；
- 不嵌入开发者个人 OpenAlex API key；
- 不把个人 sign-in credential 放进 APK；
- 若未来 production scale 需要 keyed usage，进入 backend/credential architecture 后再做。

## 3.3 DataCite

使用 public no-auth metadata API，只在 dataset/software/non-Crossref DOI evidence 下触发 targeted fallback。

## 3.4 Minimal outbound data

网络请求只能包含用户在 Query Preview 明确确认的：

- normalized DOI；或
- selected title/author/year/venue clue。

禁止发送：

- photo binary
- recording
- clip
- abstract PDF
- entire OCR corpus
- entire timeline
- export archive

## 3.5 Cached data

只持久化 normalized metadata/source observation 所需字段。

不要默认缓存 Crossref abstracts 或大块 raw payload。

# Phase 4：Lookup Orchestration / Durable Attempt / Cache

建议内部 task：

- `0.3.x_reference_repository_and_cache_task.md`

实现：

Evidence
-> Query Preview
-> `ReferenceLookupAttempt`
-> provider calls
-> partial success
-> merge/dedup/rank
-> persistence

要求：

- request fingerprint 幂等；
- offline 不发请求；
- timeout/provider unavailable/rate-limit 不阻塞本地 Reconstruction；
- partial provider success 可展示；
- manual retry；
- cancel；
- delete seminar 清理 evidence/attempt/candidates/sources/brief。

可以复用现有 WorkManager 思想。如果采用 WorkManager，必须 user-triggered、network-constrained、unique by request fingerprint；禁止 OCR 完成后自动触发 reference lookup。

普通 live lookup 不应自动无限 retry。

# Phase 6：Seminar Brief + Export

建议内部 task：

- `0.3.x_seminar_brief_model_ui_task.md`
- `0.3.x_brief_export_integration_task.md`

## Brief

一个 seminar 一个 app-owned editable Brief。

支持：

- background/context
- core question
- methods
- main results
- key takeaways
- unresolved questions
- follow-up actions
- user notes
- confirmed reference links
- key-slide links/captions

可以 prefill seminar title/speaker/date、selected questions、confirmed references、key slides 等事实/引用；不生成 AI prose。

Confirm/reject reference reversible。

## Export

扩展现有 Markdown/ZIP：

- optional Seminar Brief section
- confirmed references section
- key slides/brief captions relative media links

必须保持 deterministic renderer，补 golden tests。

不要做 BibTeX/RIS/Zotero account sync；这些属于后续。
