# SeminarArc 0.2.x Local Visual Reconstruction Master Goal

## 目标

在已经完成的 `0.1.x` Local MVP 基础上，连续完成 `0.2.x` 的 readiness 审查、技术 spike、schema/provider/design gate，以及 gate 通过后的本地视觉重建实现。

最终目标是让 seminar 照片从“只能回看”升级为“可增强、可 OCR、可搜索、可筛选关键幻灯片、可重试处理”，同时保持 local-first，不进入 `0.3.x` 的论文候选/Reference lookup，不进入转写、AI、Notion、云同步、广告或支付。

本 master goal 可以在内部自行创建多个 `prompts/tasks/<id>_task.md` / `<id>_result.md` 并连续执行；除非遇到本文定义的 hard blocker，否则不要每完成一个内部 task 就等待用户重新授权。

# Phase A：0.2.x Readiness / Research Gate

在写 production `0.2.x` 功能代码前，必须完成以下审查，并分别形成内部 task/result。

建议内部 task：

1. `0.2.x_reconstruction_schema_design_task.md`
2. `0.2.x_local_ocr_spike_task.md`
3. `0.2.x_image_enhancement_spike_task.md`
4. `0.2.x_provider_privacy_license_review_task.md`
5. `0.2.x_reconstruction_workspace_design_review_task.md`

## A1. Schema evolution design

设计从当前真实 Room schema（以仓库最新 version 为准，不要假设仍为 v1）进入 `0.2.x` 的明确 migration。

重点审计并设计：

- `SeminarAssetEntity`
- `ProcessingJobEntity`
- `OcrResultEntity`
- `TagEntity` + mapping
- 为未来 transcript/reference 预留边界，但不要在 0.2.x 提前实现不需要的功能

要求：

- 原始 recording/photo/clip/abstract 的现有 file path 和所有权不能因迁移丢失；
- migration 必须显式；
- 禁止 destructive migration；
- migration failure 不得破坏已有用户数据；
- 设计应尽量渐进，不为了“统一模型漂亮”一次重写所有 0.1.x 表。

写一份独立 schema design note/result，明确：

- 哪些现有表保留；
- 哪些新增；
- 是否需要 backfill `SeminarAssetEntity`；
- backfill 是否可幂等；
- migration version；
- rollback/failure protection；
- instrumentation test strategy。

## A2. ML Kit Text Recognition spike

必须联网查阅当前官方 Android / ML Kit 文档，而不是依赖模型记忆。

核对：

- on-device/offline behavior；
- model packaging / bundled vs dynamically downloaded model；
- English / Chinese language support；
- minSdk / target compatibility；
- dependency size；
- image input requirements；
- cancellation / threading；
- license / terms；
- 是否需要 Google Play Services；
- 在无网络时首次使用能否工作。

目标是明确 0.2.x 第一版应该选择哪种 OCR packaging strategy。

优先原则：

- local-first；
- 无网络仍能进行核心 OCR；
- 不上传 seminar photo；
- 不需要 API key；
- 商业发布许可清晰。

如果 ML Kit 不满足这些要求，必须记录 blocker / alternative，而不是强行实现。

## A3. Local image enhancement spike

比较并决定第一版图像处理实现：

- Android/Bitmap/Matrix 原生能力；
- OpenCV Android；
- 其他必要且许可清晰的本地方案。

第一版只需要支撑：

- rotate；
- crop；
- perspective correction；
- basic contrast / readability enhancement；
- thumbnail strategy。

原则：

- 原图永远保留；
- enhanced image 是 derived asset；
- 不覆盖原始 photo；
- 不提前做复杂去眩光/深度学习增强。

明确依赖体积、性能、license 和维护成本。

## A4. Provider / privacy / license gate

写清第一批 provider boundary：

- `TextOcrProvider`
- `ImageEnhancementProvider` 或等价本地 abstraction
- `CloudUploadPolicy`

并审计未来接口边界：

- `FormulaOcrProvider`
- `TranscriptionProvider`
- `SummaryProvider`
- `ReferenceLookupProvider`

但 0.2.x 不实现后四者的真实 provider。

必须明确：

- Compose UI 不直接调用 provider；
- provider output 映射为 app-owned domain model；
- cloud upload 默认禁止且必须用户主动触发；
- app secret 不嵌入 APK；
- local OCR 与未来 cloud OCR 的隐私文案区别。

## A5. Research Reconstruction workspace design review

现有 `design/` 主要覆盖 0.1.x。

在实现新 workspace 前，必须形成设计规格，而不是 Codex 自由发挥 UI。

至少定义：

- Completed seminar Detail 如何进入 `Research Reconstruction`；
- Key slides selection；
- OCR pending/running/succeeded/failed；
- photo / enhanced photo toggle；
- OCR text review/edit；
- photo tags；
- search；
- processing job retry/cancel；
- 与 Timeline 的关系；
- 不把 transcript/reference/AI 假装成已实现。

更新：

- `design/UI_SPEC.md`
- `design/USER_FLOW.md`
- `design/README.md`
- 如需要，新增 state spec / wireframe；可以先用文字/结构化 spec，不强制生成新的高保真 PNG 才能开始。

## Readiness Gate

只有以下全部满足才允许进入 Phase B production coding：

- migration design reviewed and internally consistent；
- ML Kit/offline/license 决策明确；
- image enhancement dependency 决策明确；
- provider boundary written；
- privacy/license review exists；
- Reconstruction workspace design spec 已更新；
- 没有需要用户产品决策的 unresolved conflict。

如果存在真正需要用户选择的产品冲突，停止并汇报单一决策点，不要自行猜。

# Phase B：0.2.x Data Foundation

Readiness Gate 通过后连续实现。

建议内部 task：

1. `0.2.x_asset_and_processing_job_model_task.md`
2. `0.2.x_ocr_result_and_tag_model_task.md`
3. `0.2.x_room_migration_and_backfill_task.md`

## B1. Asset model

实现最小必要的 `SeminarAssetEntity` 与 repository/domain mapping。

要求：

- 每个 asset 明确属于 `seminarId`；
- 支持 original vs derived；
- 原始 photo / enhanced photo 可关联；
- 不破坏现有 recording/photo/clip/export 代码；
- 若需要 backfill 现有媒体，过程可测试且幂等。

## B2. ProcessingJob

实现 durable job state，例如：

- `QUEUED`
- `RUNNING`
- `SUCCEEDED`
- `FAILED`
- `CANCELLED`

记录：

- job type；
- provider ID/version；
- input asset；
- timestamps；
- retryability；
- readable error。

避免把具体 ML Kit private response 写成数据库事实。

## B3. OCR result / tags

实现：

- OCR result app-owned model；
- confidence / text blocks（按第一版必要程度控制复杂度）；
- human edited state；
- key slide / background / method / result / reference / formula / follow-up 等标签；
- custom tags 的扩展边界。

## B4. Migration

增加显式 Room migration，并完成：

- JVM/schema tests；
- Windows Emulator migration instrumentation；
- 旧数据保留验证；
- existing recording/photo/clip/export 不丢失；
- migration 后 app 正常打开。

不允许 `fallbackToDestructiveMigration()`。

# Phase C：Local Image Enhancement

实现照片派生处理。

最低能力：

- rotate；
- crop；
- perspective correction；
- basic readability enhancement；
- derived image persistence；
- original image preservation；
- thumbnail / display strategy。

要求：

- output 存在于 seminar-owned app-private storage；
- 原图不可覆盖；
- failure 不删除原图；
- cancel/retry 有明确状态；
- derived asset cleanup 与 seminar deletion 一致。

Windows Emulator 运行相应 instrumentation/smoke。

不要在本阶段做：

- AI super-resolution；
- advanced glare removal；
- cloud image enhancement。

# Phase D：Local OCR Processing

实现第一版真实 local OCR provider。

建议结构：

UI
→ use case / repository
→ ProcessingJob
→ `TextOcrProvider`
→ ML Kit/local implementation
→ `OcrResultEntity`

要求：

- 只对用户选中的照片或 key slides 运行，不默认处理全部历史照片；
- job 可取消、可重试、幂等；
- app/process recreation 后状态可恢复；
- 相同 asset 不应因重复点击产生无限重复 job；
- OCR failure 不影响原图；
- OCR result 可人工编辑；
- local OCR 不上传文件；
- 无网络条件下按选定 packaging strategy 验证核心路径。

至少覆盖：

- English slide；
- Chinese slide；
- mixed English/Chinese；
- empty/low-text photo；
- missing asset；
- cancelled job；
- retry；
- duplicate request；
- process restart / WorkManager recovery（若使用 WorkManager）。

真实 OCR correctness 不要求 benchmark，但要记录 smoke evidence。

# Phase E：Search / Tags / Key Slides

实现本地可搜索、可整理能力。

包括：

- OCR text search；
- seminar scoped search；
- photo tags；
- mark/unmark key slide；
- key slides filter；
- OCR status filter；
- photo thumbnail + enhanced/original state；
- search empty/error state。

不要做跨 seminar 的全局知识库搜索，除非现有产品计划明确授权。

# Phase F：Research Reconstruction Workspace

按 Phase A 更新后的 design spec 实现真正工作区。

第一版只整合本地能力：

- key slides；
- original/enhanced image；
- OCR text；
- tags；
- user notes/questions；
- processing status；
- retry/cancel；
- editable reconstruction notes / draft fields（如果 design gate 已定义）。

明确显示未来但未实现能力时，只能作为 disabled/coming later，并避免 fake completion。

禁止在 0.2.x 实现：

- Crossref/OpenAlex reference lookup；
- DOI candidate matching；
- transcription；
- SummaryProvider/LLM；
- Notion；
- formula OCR；
- cloud upload。

这些属于后续版本。

## Hard blockers / 停止条件

普通 compile/test/lint/UI bug 不是停止条件，应自行修复。

只有以下情况允许停止 master goal：

- ML Kit/offline/license 事实证明无法满足 local-first 产品约束，且替代方案需要用户产品决策；
- migration 存在真实用户数据破坏风险，无法安全继续；
- image/OCR dependency license 不适合未来商业发布；
- Reconstruction workspace 存在需要用户选择的重大产品冲突；
- Windows Emulator 基础设施失效且没有安全 connected-test 路径；
- 继续必须操作 protected GM1910，而 task 未授权。

遇到 blocker 时保留已安全完成的 commit/push，并在 master result 中只提出最小必要决策问题。
