# 0.5.x Deterministic Photo Fixture Closeout Task

## Goal

用一个可重复、repo-safe 的 deterministic slide fixture 关闭当前 B04 Reconstruction 与 B07 Formula photo path 的 Emulator fixture blocker。

本任务不是全量 black-box rerun，也不是 provider integration。重点是：

1. 给现有 harness 增加按 scenario 选择运行的能力；
2. 让 Windows Emulator CameraX 能稳定捕获一张固定 slide；
3. focused 跑通 B04 / B07；
4. 失败时 bounded stop，不允许再次连续耗时 10+ 小时。

## Scope A — targeted scenario execution

扩展现有 harness，支持只运行指定 scenario，例如：

```powershell
.\scripts\run-blackbox-acceptance.ps1 -Scenarios B04,B07
```

参数名可按现有脚本风格调整，但必须满足：

- 默认仍可运行完整 catalog；
- 本任务可以只跑 B04/B07；
- 不为了验证一个 fixture 重复执行 B01/B02/B03/B05/B06/B08；
- final validation 才做必要的最小 regression。

如果已有等价 selective-run 能力，复用而不是重复实现。

## Scope B — deterministic slide fixture

创建一个**项目自生成、可公开提交、无版权/隐私风险**的 slide fixture。

内容应至少包含：

- 明确的大标题，例如 `SeminarArc Camera Fixture`；
- 一段英文正文；
- 一段中文正文；
- DOI clue：`10.1038/nature12373`；
- 一个简单公式，例如 `E = mc^2` 或 `y = X beta + epsilon`；
- 一个简单的图表/几何区域，便于 crop/formula region 操作。

fixture 可以由 repo 中的 deterministic source 生成，例如 SVG/HTML/Python-generated PNG；如果提交二进制 PNG，必须同时保留可复现生成方式或清晰来源说明。

不要使用真实用户 seminar 数据。

## Scope C — Emulator image-backed camera

优先使用 Android Emulator 官方支持的 image-backed camera source：

```text
-camera-back imagefile:<fixture-path>
```

或当前 Emulator 版本等价的官方 image/virtual-scene camera mechanism。

必须先现场检查当前 Emulator binary/version/AVD 实际能力，不要盲目假设参数可用。

允许对 **Windows Emulator 本身** 做必要的 stop/restart/relaunch，前提是：

- 只作用于明确 emulator target；
- 不运行 `adb kill-server`；
- 不碰 GM1910 / `8cc54656`；
- 不运行 usbipd / WSL transport reset；
- 所有 ADB 非 inventory 命令仍显式 `-s <emulator>`。

如果当前 AVD 无法安全用 imagefile source，可以创建/使用专门的 QA AVD，但不要修改 production app 去加入 test-only media injection backdoor。

## B04 closeout target

在固定 slide fixture 下，黑盒完成：

1. `Capture Slide` 产生真实 saved photo asset；
2. Reconstruction workspace 可见 photo preview；
3. image enhancement 可运行并完成；
4. OCR job 可运行并完成；
5. OCR UI 可见，并可编辑至少一处文本；
6. key-slide toggle 可操作；
7. force-stop / relaunch 后 photo / OCR edit / key-slide 状态保持。

Exact OCR 文本可以做合理断言，但不要把 ML Kit 的轻微识别差异当成基础流程失败。至少应验证 fixture 的一个稳定 clue（如标题片段或 DOI）能被观察到；若内容质量明显异常，记录 evidence。

## B07 closeout target

复用同一 saved photo：

1. formula region create；
2. drag-to-draft selection；
3. 显式保存；
4. reopen/edit crop 或 label；
5. live Formula OCR unavailable state 正确；
6. manual LaTeX 输入并持久化；
7. force-stop / relaunch 后 formula result 仍在。

本任务不需要重跑 B07 已经通过的所有 Markdown/ZIP/BibTeX/RIS/Notion-ready export 文件验证；只需做一个最小 export sanity check，避免重复浪费时间。

## Runtime / stop policy

本任务必须明显短于上一轮 research-flow harness。

- 优先只跑 B04/B07；
- 单次 fixture approach 最多做有限 retry；
- 同一种方式连续失败后不要无限微调；
- 最多尝试两种合理的官方 Emulator fixture 方案；
- 如果两种都不能稳定产生 saved photo，写出 `BLOCKED_EMULATOR_CAMERA_FIXTURE` result 并停止，不要继续耗时探索第三、第四套大型方案；
- 普通 ADB/UI timeout 继续遵守现有 30–60s 规则；
- 每 15–30s 输出一次状态；
- 不通过重启 ADB server / USB / WSL 来解决问题。

建议目标：focused closeout 控制在约 1–2 小时级别，而不是全天运行。

## Regression

如果 production code 未修改：

- focused B04/B07 closeout；
- 必要的 harness self-check；
- 不要求无意义地再次跑全量 66-step catalog。

如果 production code 有修改：

- 补 focused unit/instrumentation regression；
- `testDebugUnitTest assembleInternal lintDebug`；
- 按 `docs/DEVICE_TESTING.md` 运行批准的 Emulator regression；
- 最后可以只做一轮基础 smoke，而不是反复全量黑盒。

## Provider freeze

- OpenAI API；
- Mathpix；
- live ASR；
- live LLM summary；
- live Formula OCR；
- Notion OAuth/backend；
- Mac mini local model integration。

这些 provider/runtime 决策延后到 2026-10 单独评估；当前继续保留 provider boundary/unavailable behavior。
